# 단계적 2D 이관 기획 경계 검토

## 요약

- 이 작업은 신규 게임 범위를 추가하는 작업이 아니라, 이미 승인된 `쥐 숙주 1차 프로토타입` 핵심 루프를 현재의 2D 아이소메트릭 구조로 옮기는 순서와 경계를 승인받기 위한 문서 작업이다.
- 2026-07-27 사용자 승인에 따라 현재 제작 기준은 `2D 아이소메트릭/쿼터뷰 도트 게임`이다. 2026-07-16의 3D 환경·저폴리 원본 기반 하이브리드 2.5D 방향은 신규 제작 기준에서 제외되며, 기존 구현과 산출물은 레거시 비교·회귀 자료로 보존한다.
- 완료된 `RatHost2DTechnicalSample`은 쥐 이동, 2D 충돌, 카메라 추적, 방향 표시, Y 정렬과 HUD의 기술 성립을 확인한 샘플이다. 면역 경계도, 모드 전환, 내부 바이러스 미니게임, 변이 선택·복귀까지 이관된 것은 아니다.
- 추천 이관 순서는 `1단계 숙주·면역·전환 → 2단계 내부 바이러스 미니게임 → 3단계 변이 선택·복귀`다. 각 단계는 별도 플레이·회귀 검증이 가능해야 하며, 다음 단계로 넘어가기 전에 직전 단계의 수용 결과를 남긴다.
- 원본 `.docx`의 과거 저폴리 3D 방향과 현재 Markdown 문서의 2D 방향이 다를 경우, 현 작업에서는 2026-07-27 승인 이력이 반영된 Markdown 문서를 현재 해석 기준으로 사용한다. 원본 초안은 기획 원형과 이력으로 보존한다.

## 확정 사항

### 현재 방향

- 엔진은 Unity, 버전은 `6000.4.6f1`, 렌더 파이프라인은 URP, 1차 플랫폼은 PC다.
- 현재 비주얼·공간 표현은 3D 환경과 프리렌더 스프라이트를 결합한 2.5D가 아니라, 환경·캐릭터·효과를 2D 타일과 스프라이트로 구성하는 아이소메트릭/쿼터뷰 도트 방식이다.
- 환경과 이동 공간은 2D 아이소메트릭 타일맵 또는 동등한 2D 레이어, 이동과 판정은 2D 물리·충돌 영역, 표시 순서는 가림과 Y축 깊이 정렬을 기준으로 한다.
- 쥐·바이러스·백혈구는 일관된 체형과 픽셀 밀도를 가진 방향별 2D 스프라이트로 표시한다.
- 목표 목업과 ChatGPT 생성 이미지는 분위기·구도·형태를 판단하는 reference 또는 후보이며, 실제 타일셋·스프라이트 시트·애니메이션 프레임·충돌 데이터·최종 에셋이 아니다.

### 쥐 숙주 1차 프로토타입 기능 경계

- 작은 하수도 맵에서 `WASD`로 쥐 숙주를 조종하고 `Space`로 상호작용한다.
- 현재 구현 기본값 `PrototypeConfig.BaseAlertPerSecond=0`에 따라 무입력 시간 경과만으로 면역 경계도는 상승하지 않는다. 위험 행동으로 경계도가 자연스럽게 100%에 도달하며, 100% 도달 이벤트는 한 번만 발생한다.
- 면역 경계도 100%에서 내부 바이러스 미니게임으로 전환한다.
- 내부 미니게임에서 바이러스를 조종해 백혈구 1종을 피하고 변이 조각 3개를 수집한다.
- 바이러스 안정도가 0이 되기 전에 조각 3개를 모으면 성공하며, 안정도가 0이 되면 실패한다.
- 성공 시 세 가지 변이 중 하나를 선택한 뒤 쥐 숙주 모드로 복귀한다.
- 실패 시 변이 보상 없이, 성공 복귀보다 높은 면역 압박을 남긴 채 쥐 숙주 모드로 복귀한다.
- 성공과 실패가 같은 프레임에 성립하면 성공을 우선한다.
- 프로토타입 변이는 `잠복 강화`, `신경 조종`, `포유류 적응` 세 가지이며, `포유류 적응`은 다중 숙주 전이가 아니라 하수도 내 특정 통로 접근 허용으로만 검증한다.

### 기술 샘플과 레거시 경계

- 별도 2D 기술 샘플은 쥐 이동, 벽·수로·소품 충돌, 방향 표시, 카메라, Y 정렬과 최소 HUD를 검증한 것으로 사용자 수용을 받았다.
- 기술 샘플의 수용은 전체 핵심 루프의 2D 이관 승인이나 완료를 의미하지 않는다.
- 기존 `RatHostPrototype.unity` 3D 플레이어블, 관련 코드·검증 자료, 2.5D/Blender 원본과 프리렌더 산출물은 2D 핵심 루프가 검증될 때까지 비교·회귀 기준으로 보존한다.
- 기존 3D 자료를 삭제하거나 덮어쓰는 것은 이번 브리프 범위에 포함되지 않는다.

## 단계적 이관 추천안

### 1단계: 2D 쥐 숙주·면역 경계도·모드 전환

포함:

- 수용된 2D 이동·충돌·카메라·Y 정렬 기반
- 쥐 숙주 생명력과 면역 경계도
- 승인된 위험 행동에 따른 경계도 상승과 자연스러운 100% 도달
- 경계도 100% 단일 이벤트
- 쥐 모드 입력·UI·충돌 비활성화와 내부 모드 진입 경계
- 전환 직전 숙주 상태 저장

제외:

- 실제 내부 바이러스 플레이
- 백혈구, 변이 조각, 성공·실패 판정
- 변이 선택과 효과 적용

수용 기준:

- 쥐 이동·충돌·카메라·가림 회귀가 없다.
- 무입력 상태에서 의도하지 않은 이동이나 면역 경계도 상승이 없다.
- 어떤 위험 행동이 면역 경계도를 올렸는지 UI 피드백으로 이해할 수 있고, 위험 행동만으로 100%에 자연스럽게 도달할 수 있다.
- 100% 이벤트와 모드 전환 요청이 한 번만 발생한다.
- 전환 시 이전 쥐 입력·충돌·HUD가 중복 동작하지 않는다.

### 2단계: 2D 내부 바이러스 미니게임과 성공·실패 복귀 경계

포함:

- 바이러스 이동
- 백혈구 적 1종과 접촉 판정
- 바이러스 안정도
- 변이 조각 3개 수집
- 성공·실패 우선순위
- 실패 UI와 보상 없는 쥐 모드 복귀
- 백혈구 접촉의 `면역 포착 +8` 흔적 및 복귀 규칙

제외:

- 변이 선택 UI
- 신규 변이 또는 성장 계열
- 두 번째 숙주와 전이 시스템

수용 기준:

- 미니게임 진입 후 쥐 모드 입력·UI·충돌이 작동하지 않는다.
- 조각 3개 수집과 안정도 0 판정이 문서 규칙대로 작동한다.
- 성공·실패 동시 판정 시 성공이 우선된다.
- 실패 후 새 변이가 지급되지 않고, 초기화·유지 항목이 구분돼 쥐 모드로 복귀한다.
- 재진입 시 이전 미니게임의 조각·백혈구·패널 상태가 잘못 남지 않는다.

### 3단계: 변이 선택·효과 적용·전체 루프 복귀

포함:

- 성공 후 세 가지 변이 선택
- 선택 1회 확정과 중복 지급 방지
- `잠복 강화`, `신경 조종`, `포유류 적응`의 승인된 임시 효과
- 변이 적용 상태로 쥐 숙주 모드 복귀
- 성공 루프와 실패 루프의 전체 상태 회귀

제외:

- 정식 다중 숙주 전이
- 숙주 경험 특성 계승
- 영구 성장과 완성형 로그라이크 런

수용 기준:

- 세 선택지가 표시되고 하나만 적용된다.
- 각 변이 효과가 쥐 숙주 플레이에서 구분 가능하다.
- `포유류 적응`은 특정 하수도 통로 접근만 허용하며 새 숙주를 만들지 않는다.
- 성공 복귀와 실패 복귀의 보상·면역 경계도 차이가 유지된다.
- Windows 빌드에서 쥐 모드 시작부터 성공 또는 실패 복귀까지 각각 한 번 이상 완료할 수 있다.

## 재사용·교체 경계

### 재사용 원칙 후보

- 이미 승인된 게임 규칙, 상태 이름, 성공·실패 우선순위, 변이 효과와 초기화·유지 규칙은 보존한다.
- Unity 3D 표현이나 `Collider`에 직접 의존하지 않는 순수 상태 로직과 EditMode 테스트는 실제 의존성을 대조한 뒤 재사용하는 방향이 적절하다.
- 공용 게임 상태, 면역 경계도, 모드 전환, 변이 선택처럼 표시 방식과 분리 가능한 모듈은 2D 표현 계층과 느슨하게 연결하는 것을 추천한다.

### 교체 대상

- 3D 이동, 3D Collider/Rigidbody, 3D 카메라, 3D 공간 좌표와 직접 결합된 판정은 2D 이동·Collider2D/Rigidbody2D·고정 2D 카메라 구조로 교체한다.
- 3D 모델·프리렌더 파이프라인을 신규 2D 캐릭터 제작 기본 경로로 사용하지 않는다.
- 3D 깊이 또는 월드 Z에 기대는 앞뒤 표시는 발 접지점 기준 Y 정렬과 명시적 가림 레이어로 교체한다.

### 주의

- `기획 규칙 재사용`과 `기존 C# 코드 그대로 재사용`은 같은 결정이 아니다. 실제 코드 재사용 범위는 의존성 조사와 테스트 대조 후 확정해야 한다.
- 기술 샘플 코드를 그대로 확장할지, 검증된 구성요소만 새 프로토타입 씬으로 옮길지는 사용자 승인 전 확정 사항이 아니다.

## 미확정 사항

- 실제 2D 이관의 첫 구현을 1단계만 시작할지, 1~2단계를 한 작업으로 묶을지
- `RatHost2DTechnicalSample.unity`를 계속 확장할지, 별도 `RatHost2DPrototype` 계열 씬을 만들어 검증된 구성요소만 승격할지
- 기존 상태 로직 중 실제로 2D와 무관해 재사용 가능한 코드·테스트의 범위
- 2D 전체 핵심 루프가 어느 검증 수준에 도달했을 때 기존 3D 플레이어블을 기본 실행·빌드 대상에서 제외할지
- 내부 바이러스 모드를 탑다운으로 둘지, 숙주 모드와 같은 고정 쿼터뷰로 둘지
- 현재 비활성인 시간 경과 기본 상승(`PrototypeConfig.BaseAlertPerSecond=0`)을 다시 활성화할지와, 활성화한다면 상승 속도를 얼마로 둘지
- 최종 내부 기준 해상도, 타일 크기, PPU, 캐릭터 프레임 크기, 동작별 프레임 수와 재생 속도
- 최종 타일셋, 쥐·바이러스·백혈구 스프라이트, 소품, 효과, HUD의 외형과 팔레트
- 기술 샘플의 `960×540`, `64×32`, `PPU 64`, `8방향×2프레임`, `6 fps` 후보를 프로젝트 공통 규격으로 승격할지
- Windows 실행본 플레이 미검증 잔여 위험을 1단계 구현 시작 전에 별도 해소할지, 각 단계 빌드 검증에 포함해 해소할지

## 사용자 승인 질문

1. **1차 구현 단계**
   먼저 `2D 쥐 숙주 이동·충돌 + 면역 경계도 + 100% 모드 전환 경계`까지만 구현하고, 내부 미니게임은 다음 단계로 분리해도 되는가?

2. **씬 전략**
   기술 검증 이력을 보존하기 위해 `RatHost2DTechnicalSample`은 그대로 두고, 별도 2D 핵심 루프 프로토타입 씬을 만들어 검증된 이동·충돌·카메라·정렬 구성만 승격해도 되는가?

3. **상태 로직 재사용 원칙**
   기존 3D와 무관한 공용 상태·면역·모드 전환·변이 규칙과 테스트는 우선 재사용하고, 3D 물리·카메라·표현 의존부만 2D로 교체하는 원칙을 승인하는가?

4. **기존 3D 보존 시점**
   기존 3D 플레이어블은 2D 전체 루프의 성공·실패 복귀, Windows 빌드, 사용자 플레이가 모두 통과할 때까지 회귀 기준으로 유지하고, 그 뒤에도 삭제하지 않고 레거시 씬으로 보관해도 되는가?

5. **구현 착수**
   위 1단계 범위와 씬·재사용·레거시 보존 원칙을 승인한 뒤 실제 Unity 코드·씬·테스트 구현 작업을 시작해도 되는가?

6. **시간 경과 면역 상승**
   1단계에서는 현재 구현과 동일하게 무입력 시간 상승을 `0`으로 유지하고 위험 행동만으로 100%에 도달하게 할 것인가? 시간 경과 기본 상승을 다시 켜려면 상승 속도와 의도를 별도 승인할 것인가?

## 기획 정리 에이전트 추천 판정

- 추천안: `1단계만 우선 구현`, `기술 샘플 보존 + 별도 2D 프로토타입 씬`, `순수 상태 로직·테스트 선별 재사용`, `기존 3D 레거시는 전체 2D 루프 수용 후에도 삭제하지 않고 보관`.
- 사용자 결정 필요: 위 추천안은 현재 문서 정합상 가장 안전한 이관 순서지만, 실제 구현 단계·씬 전략·코드 재사용·레거시 기본 대상 전환 시점을 새로 결정하므로 사용자 승인이 필요하다.
- 최종 규격 경계: 기술 샘플의 PPU·타일·해상도·프레임 시험값과 플레이스홀더 아트는 이번 승인 질문에 포함하지 않으며, 별도 비교·아트 브리프·사용자 수용 전에는 최종으로 확정하지 않는다.
