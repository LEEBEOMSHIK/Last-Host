# 쥐 숙주 핵심 루프 단계적 2D 이관 검토

작성일: 2026-07-27
담당 역할: 게임플레이 루프 에이전트
문서 성격: 승인 브리프 입력용 검토안. 구현 승인이나 최종 기술 규격이 아니다.

## 1. 검토 결론

쥐 숙주 핵심 루프는 다음 세 단계로 이관하는 것이 적절하다.

1. `2D 쥐 숙주 탐험 + 면역 경계도 + 100% 모드 인계`
2. `2D 내부 바이러스 미니게임 + 성공·실패 분기`
3. `변이 선택 + 2D 쥐 숙주 복귀 + 변이 효과 체감`

게임플레이 루프 관점의 **추천 1차 구현 범위는 1단계만**이다. 이미 사용자 수용을 받은 2D 기술 샘플의 이동·충돌·카메라·Y 정렬 계약에 기존 면역 상태와 모드 전환을 결합하면, 문제 발생 시 원인을 `2D 탐험 계층`과 `내부 미니게임 계층` 사이에서 분리할 수 있다.

이 추천은 구현 지시가 아니다. 다음 사항은 사용자 최종 승인이 필요하다.

- 1차 구현을 1단계로 제한할지
- 기술 샘플을 직접 확장할지, 별도 2D 프로토타입 씬을 만들지
- 기존 핵심 상태 로직의 조건부 재사용 원칙
- 기존 3D 씬을 언제까지 회귀 기준으로 보존할지

## 2. 루프와 기존 자산의 경계

### 2.1 원칙

- `상태·규칙`은 2D/3D 표현과 무관하므로 우선 재사용 대상으로 본다.
- `입력 해석·물리·카메라·표시·씬 참조`는 3D 결합 여부를 대조해 2D 계층으로 교체한다.
- 상태 모델 재사용은 기존 동작의 유지이지, 기존 MonoBehaviour와 3D 씬 구조를 그대로 복제한다는 뜻이 아니다.
- 기술 샘플의 수치는 시험값이다. `960×540`, `64×32`, `PPU 64`, 이동 속도, 임시 충돌 크기와 플레이스홀더를 최종 규격으로 확정하지 않는다.
- 기존 `RatHostPrototype.unity`와 3D 검증 자료는 3단계 전체 루프의 Windows 플레이 수용 전까지 삭제하거나 대체하지 않는다.

### 2.2 재사용·교체 후보

| 구분 | 후보 | 제안 |
| --- | --- | --- |
| 순수 상태·규칙 | `PrototypeSessionState`, `PrototypeConfig`, `PrototypeGameMode` | 재사용 우선. 각 단계의 상태 전이 회귀 테스트를 먼저 고정한다. |
| 면역 규칙 | `ImmuneAlertModel`, `ImmuneAlertEvent`, `ImmuneAlertCauseType` | 재사용. 현재 `BaseAlertPerSecond = 0`인 무위험 대기 증가 0, 원인이 표시되는 위험 행동 가산, 100% 단일 발행, 복귀값 규칙을 유지한다. |
| 내부 미니게임 규칙 | `VirusMinigameModel`, `VirusMinigameOutcome` | 2단계에서 재사용. `조각 3개`, `안정도 0`, 동시 성공·실패 시 성공 우선 계약을 유지한다. |
| 변이 규칙 | `MutationLoadout`, `MutationType`, `MutationDefinition` | 3단계에서 재사용. 세 효과의 수치는 기존 프로토타입 기준을 유지하되 별도 밸런스 확정으로 해석하지 않는다. |
| 세션 조정 | `PrototypeSessionController` | 상태 전이 의도는 재사용하되, 구체적인 3D `RatHostController`·씬 루트 참조는 2D 어댑터 또는 새 조정 계층으로 분리한다. |
| 쥐 이동·충돌 | 기존 `RatHostController` 및 3D 충돌 | 2D 경로에서는 교체. 기술 샘플의 `Movement2DModel`, `RatHost2DController`가 검증한 화면 기준 WASD·Rigidbody2D·Collider2D 계약을 계승한다. |
| 방향·표시 | 기존 3D/2.5D 표시 컴포넌트 | 2D 방향 스프라이트 표시로 교체. 물리 루트와 시각 루트를 분리하고 프레임 교체가 판정 위치를 바꾸지 않게 한다. |
| 카메라·깊이 | `PrototypeCameraController`, 3D 깊이 | `PixelFollowCamera2D`, `YSortOrder2D`가 검증한 행위 계약으로 교체한다. |
| 위험·상호작용 | 3D Trigger/Collider 기반 `ImmuneRiskZone`, `RatRiskInteractable` | 면역 이벤트 의미는 유지하고 감지는 `Collider2D`/`Trigger2D` 경계로 교체한다. 중복 진입·재진입 가산을 별도 검증한다. |
| 내부 미니게임 표시·물리 | `VirusPlayerController`, `WhiteBloodCellChaser`, `MutationFragmentPickup`의 3D 결합 부분 | 2단계에서 2D Rigidbody2D/Collider2D 및 2D 표시 계층으로 교체한다. 순수 결과 판정은 상태 모델에 남긴다. |
| HUD | `PrototypeHud` | 상태 필드와 문구 계약은 참고하되, 2D 화면용 HUD 바인딩은 새로 구성한다. 기술 샘플 진단 HUD를 최종 게임 HUD로 승격하지 않는다. |

### 2.3 기술 샘플의 지위

기술 샘플에서 이미 검증된 것은 다음 행위 계약이다.

- 화면 기준 WASD와 대각선 정규화
- 무입력 정지와 방향 반전 시 무순간이동
- 2D 벽·수로·소품 충돌
- 논리 위치를 함께 따르는 카메라
- 발 접지점 기준 Y 정렬
- 16:9에서의 최소 HUD 가독성

기술 샘플에서 아직 검증하지 않은 것은 다음이다.

- 면역 경계도와 위험 이벤트
- 100% 모드 인계
- 내부 바이러스 아레나
- 성공·실패 결과
- 변이 선택과 변이 효과 적용
- 전체 루프 Windows 실행본 플레이

따라서 기술 샘플 통과를 핵심 루프 이관 완료로 간주해서는 안 된다.

## 3. 단계 1 — 2D 쥐 숙주 탐험·면역·모드 인계

### 루프 단계

`2D 하수도 등장 → 쥐 이동·탐험 → 원인이 보이는 위험 행동으로 면역 상승 → 100% → 내부 모드 진입 상태`

### 입력

- `WASD`: 화면 기준 8방향 이동
- `Space`: 관심 지점 또는 위험 상호작용
- 소음 배관, 오염 구역 체류, 독성 물웅덩이 접촉 등 승인된 위험 행동 1종 이상
- 무위험 대기와 일반 이동은 면역 경계도 입력으로 취급하지 않음

### 처리

- Rigidbody2D·Collider2D 기반 이동과 장애물 차단
- 쥐 물리 루트와 방향 스프라이트 표시 루트 분리
- `PrototypeConfig.BaseAlertPerSecond = 0` 유지
- 무위험 대기·일반 이동의 면역 경계도 증가 0
- 위험 행동의 면역 상승과 `원인 라벨 + 변화량` 피드백
- 면역 경계도 100% 도달 이벤트 단일 발행
- `RatHost → InternalVirus` 상태 인계
- 인계 즉시 쥐 입력·충돌·상호작용·위험 가산 중지
- 내부 모드 목적지 루트와 해당 모드 HUD 활성화

1단계의 내부 모드 목적지는 **플레이 가능한 미니게임 완성본이 아니라 모드 인계 검증용 착지 상태**다. 일반 플레이 빌드가 진행 불가능한 상태로 끝나지 않도록 1단계 산출물은 기술 검증 빌드로 명시하거나, 검증 전용 복귀 기능을 개발 전용으로 제한한다.

### 출력

- 쥐의 연속적인 2D 위치·방향·가림
- 충돌 가능한 벽·수로·소품
- 면역 경계도 값과 상승 원인 피드백
- 100%에서 내부 모드로 정확히 한 번 전환된 상태
- 이전 쥐 모드의 입력·UI·위험 판정 비활성

### UI

- 숙주 생명력
- 면역 경계도
- 현재 모드
- 위험 상승 원인과 증가량의 짧은 피드백
- `Space` 상호작용 가능 상태
- 내부 모드 착지 시 전환 이유와 다음 목표를 식별할 최소 안내

### 수용 기준

- 기술 샘플에서 수용된 WASD·대각선 정규화·무입력 정지·반전 무순간이동·2D 충돌·카메라 중심·Y 정렬 계약이 그대로 통과한다.
- 무위험 지역에서 대기하거나 일반 이동만 할 때 면역 경계도 증가는 0이다.
- 위험 요소 1종은 접촉 또는 상호작용 1회당 정의된 면역 증가를 정확히 적용하고, 증가 원인을 HUD에서 식별할 수 있다.
- 실제 위험 행동을 반복하거나 서로 다른 위험을 누적해 자연스럽게 100%에 도달할 수 있다. 디버그 강제 전환은 플레이 수용 근거로 사용하지 않는다.
- 100% 미만에서는 모드가 유지되고, 최초 100% 도달 시 `InternalVirus` 전환이 정확히 1회 발생한다.
- 전환 프레임 이후 쥐 위치, 입력, 위험 Trigger가 세션 상태를 추가 변경하지 않는다.
- 내부 모드 착지 화면에서 플레이어가 `면역 경계도 100% 때문에 전환되었다`는 사실을 설명 없이 이해할 수 있다.
- 기존 3D 씬·상태 테스트·기술 샘플 회귀 테스트에 신규 실패가 없다.

### 테스트 시나리오

1. 무위험 지역에서 충분히 대기해 면역 경계도 증가가 정확히 0이고 무입력 위치 드리프트도 0인지 함께 측정한다.
2. 위험 요소를 건드리지 않고 일반 이동해 면역 경계도 증가 0, 카메라 중심, Y 정렬을 동시에 확인한다.
3. 위험 요소에 진입·정지·이탈·재진입해 중복 가산과 재진입 규칙을 확인한다.
4. 소음 배관 상호작용 또는 승인된 오염 접촉·체류를 반복해 디버그 강제값 없이 100%에 도달하고 전환 이벤트가 한 번만 발생하는지 확인한다.
5. 경계도가 `99.x`인 경계 사례에서 위험 행동 가산으로 100%를 넘기고, 같은 프레임에 위험 이벤트가 중복 제출되어도 전환이 한 번인지 확인한다.
6. 전환 직후 WASD·Space를 유지해 쥐 이동, 상호작용, 면역 추가 상승이 없는지 확인한다.
7. 2D 씬을 재시작해 초기 모드·초기 면역·쥐 위치가 결정론적으로 복원되는지 확인한다.
8. `잠복 강화` 적용 여부와 관계없이 현재 기본 시간 상승이 0으로 유지되는지 확인하고, 이 단계에서 승인되지 않은 시간 상승 재활성화나 위험 가산량 변경이 섞이지 않았는지 확인한다.
9. 기존 3D 핵심 상태 EditMode 테스트와 2D 기술 샘플 전체 테스트를 함께 실행한다.
10. Unity MCP Play에서 쥐 모드 시작, 면역 HUD, 위험 요소, 100% 전환, 쥐 루트 비활성을 확인하고 Console Error/Warning을 집계한다.

### 제외 범위

- 플레이 가능한 내부 바이러스 아레나
- 백혈구 추적, 변이 조각, 바이러스 안정도 감소
- 성공·실패 판정
- 변이 선택·적용·정상 복귀
- 시간 경과 기본 면역 경계도 상승 재활성화
- 잠복 강화가 위험 행동 상승량까지 줄이도록 효과를 확장하는 변경
- 최종 HUD 디자인, 최종 타일·스프라이트·PPU 확정
- 기존 3D 씬 삭제 또는 Build Settings 대체

### 선후 의존성

- 선행: 완료된 2D 기술 샘플의 동작 계약과 회귀 테스트
- 후행: 2단계 내부 미니게임
- 차단 조건: 100% 전환 중복, 전환 후 쥐 입력 잔존, 기존 기술 샘플 이동·카메라 회귀 중 하나라도 발생

## 4. 단계 2 — 2D 내부 바이러스 미니게임·성공/실패

### 루프 단계

`InternalVirus 진입 → 바이러스 이동 → 백혈구 회피·변이 조각 3개 수집 → 성공 또는 안정도 0 실패`

### 입력

- `WASD`: 바이러스 이동
- 백혈구 접촉
- 변이 조각 Trigger 진입
- 실패 패널의 `Space` 또는 승인된 확인 입력

### 처리

- 2D 바이러스 Rigidbody2D·Collider2D 이동
- 2D 백혈구 적 1종의 추적 또는 승인된 회피 압박
- 변이 조각의 중복 수집 방지
- 백혈구 접촉 시 안정도 감소
- 접촉마다 `면역 포착 +8` 흔적 누적
- 조각 3개 수집 시 성공
- 안정도 0 시 실패
- 성공과 실패가 같은 프레임이면 성공 우선
- 성공 시 `MutationSelection`으로 인계
- 실패 시 `VirusFailed` 패널을 보여주고 확인 후 보상 없이 `RatHost`로 복귀
- 실패 복귀 시 성공 복귀보다 높은 면역 경계도 유지

공식 최소 루프의 우선 대상은 `백혈구 회피형` 한 종류다. 기존 코드에 존재하는 면역 신호 억제형 미니게임은 삭제하지 않되, 이번 2D 최소 이관의 완료 조건에는 포함하지 않는다.

### 출력

- 바이러스 위치·방향과 백혈구 위치
- 변이 조각 수
- 바이러스 안정도
- 면역 포착 흔적
- 성공 시 변이 선택 상태
- 실패 시 실패 UI와 보상 없는 쥐 모드 복귀

### UI

- 현재 모드
- 바이러스 안정도
- `변이 조각 n/3`
- `백혈구 회피 / 변이 조각 수집` 목표
- 접촉 시 `면역 포착 +8` 피드백
- 실패 제목 `면역 반응 돌파 실패`와 복귀 확인
- 성공 시 변이 선택 화면으로 인계되었음을 식별할 상태

### 수용 기준

- 1단계의 100% 전환을 통해 실제 2D 내부 모드에 진입한다.
- 바이러스 이동은 화면 기준 WASD와 대각선 속도 정규화를 유지한다.
- 각 조각은 한 번만 집계되고 세 번째 조각에서 성공이 정확히 한 번 발생한다.
- 백혈구 접촉은 설정된 안정도 피해와 `면역 포착 +8`을 한 접촉 규칙에 맞게 적용하며 프레임 중복 피해가 없다.
- 안정도 0에서 실패가 한 번 발생하고 변이 선택지가 나오지 않는다.
- 성공·실패 동시 조건에서는 성공으로 판정된다.
- 실패 확인 후 바이러스 안정도, 조각, 조각 활성 상태, 백혈구 시작 상태, 실패 패널이 초기화된다.
- 실패 복귀 후 기존 변이는 유지되고 새 변이는 추가되지 않으며 면역 경계도는 성공 복귀 기준보다 높다.
- 1단계의 쥐 이동·충돌·면역·전환과 기존 3D 상태 회귀가 유지된다.

### 테스트 시나리오

1. 1단계 경로로 100%를 만든 뒤 내부 모드의 바이러스·백혈구·조각·HUD 활성과 쥐 루트 비활성을 확인한다.
2. 조각 1개를 여러 프레임 접촉해 수집 수가 1만 증가하는지 확인한다.
3. 조각을 세 개 순서대로 수집해 `Running → Success → MutationSelection` 단일 전이를 확인한다.
4. 백혈구와 한 번 접촉해 안정도 피해와 `면역 포착 +8`을 확인하고, 분리 후 재접촉 규칙을 확인한다.
5. 안정도를 0으로 만들어 `VirusFailed`가 한 번 발생하고 변이 패널이 비활성인지 확인한다.
6. 세 번째 조각 수집과 치명 접촉을 같은 판정 프레임에 주어 성공 우선을 확인한다.
7. 실패 확인 후 쥐 모드로 복귀해 새 변이 없음, 높은 복귀 면역값, 위험 구역 재진입 유예, 내부 오브젝트 초기화를 확인한다.
8. 성공 후 변이 선택 상태에서 바이러스 이동·백혈구 피해·추가 조각 수집이 멈추는지 확인한다.
9. 내부 모드 진입·실패 복귀를 3회 반복해 잔존 Trigger, 중복 적, 누적 조각 오브젝트가 없는지 확인한다.
10. Unity MCP Play에서 성공 경로와 실패 경로를 각각 확인하고 Console Error/Warning을 집계한다.

### 제외 범위

- 면역 신호 억제형의 2D 이관 완료 주장
- 복수 백혈구 종류, 항체 패턴, 보스
- 절차 생성 아레나
- 변이 선택 결과의 실제 효과 적용
- 영구 사망, 런 종료, 저장·불러오기
- 최종 바이러스·백혈구·이펙트 아트

### 선후 의존성

- 선행: 1단계의 `RatHost → InternalVirus` 단일 인계
- 후행: 3단계 변이 선택·성공 복귀
- 차단 조건: 성공/실패 이중 판정, 실패 후 변이 지급, 접촉 프레임 중복 피해, 내부 오브젝트 초기화 누락

## 5. 단계 3 — 변이 선택·2D 쥐 숙주 복귀·효과 체감

### 루프 단계

`내부 미니게임 성공 → 세 변이 중 하나 선택 → 상태 적용 → 2D 쥐 숙주 복귀 → 변화 체감`

### 입력

- 변이 카드 클릭 또는 `1/2/3`
- 승인된 확인 입력
- 복귀 후 `WASD`, `Space`, 위험 행동과 특정 통로 접근

### 처리

- `잠복 강화`, `신경 조종`, `포유류 적응` 세 선택지 표시
- 선택 가능 상태에서만 1개 적용
- 중복 입력·다중 버튼 입력에도 선택 이벤트 단일 처리
- 성공 복귀 면역값에 내부의 면역 포착 누적값 반영
- 내부 미니게임 상태와 포착 피드백 초기화
- 쥐 모드 복귀 유예 적용
- 복귀 시 세션 진행과 기존 변이 유지
- 선택 변이에 따른 효과:
  - 잠복 강화: 기존 상태에는 기본 시간 상승 배율 감소가 있으나 현재 `BaseAlertPerSecond = 0`이므로 자연 플레이 체감이 발생하지 않는다. 시간 상승 재활성화 또는 위험 행동 상승 억제로의 효과 변경 중 어느 쪽도 별도 사용자 승인 없이 적용하지 않는다.
  - 신경 조종: 쥐 이동 속도와 조종력 개선
  - 포유류 적응: 하수도 특정 통로 접근 허용

### 출력

- 선택한 변이 1개와 효과 설명
- 변이가 적용된 세션 상태
- 복귀한 2D 쥐와 기존 탐험 상태
- 내부 포착값을 포함한 복귀 면역 경계도
- 선택한 변이에 따라 달라진 이동·면역·통로 접근 결과

### UI

- 세 변이의 이름과 프로토타입 효과
- 현재 선택 가능 상태
- 선택 완료 피드백
- 쥐 모드 복귀 후 보유 변이 표시
- 복귀 면역 경계도와 현재 모드
- 포유류 적응 통로의 잠금/해제 피드백

### 수용 기준

- 성공한 경우에만 변이 선택 화면이 나온다.
- 선택지는 정확히 세 개이며, 한 번의 성공 보상에서 정확히 한 변이만 적용된다.
- 선택 후 `MutationSelection → RatHost` 전이가 정확히 한 번 발생한다.
- 내부에서 쌓인 면역 포착값이 성공 복귀 면역값에 정확히 더해진다.
- 복귀 후 바이러스·백혈구·조각·변이 패널 입력은 비활성이고 쥐 입력만 활성이다.
- 잠복 강화 선택은 기존 변이 상태에 정확히 기록된다. 다만 현재 기본 시간 상승이 0이므로, 별도로 승인된 체감 효과 규칙이 없으면 `잠복 강화 효과 체감 완료`를 주장하지 않는다.
- 신경 조종은 같은 시간의 쥐 이동 거리와 조종력 상태를 기존 프로토타입 기준대로 변경하며 순간이동·카메라 분리를 만들지 않는다.
- 포유류 적응은 지정 통로만 열고 다른 충돌 경계를 무효화하지 않는다.
- 실패 경로에서는 새 변이가 지급되지 않는다.
- 테스터가 어떤 변이를 얻었고 쥐 플레이가 어떻게 바뀌었는지 설명 없이 식별할 수 있다.
- 성공과 실패의 전체 루프가 Windows 실행본에서 각각 한 번 이상 완료된다.

### 테스트 시나리오

1. 성공 후 세 카드의 이름·효과·입력 대응을 확인하고 선택 전에는 쥐 모드로 복귀하지 않는지 확인한다.
2. 같은 프레임에 여러 선택 입력을 주어 한 변이만 적용되는지 확인한다.
3. 잠복 강화를 선택한 뒤 무위험 대기에서 선택 전후 모두 면역 증가 0인지 확인한다. 별도 승인으로 체감 규칙이 정해졌다면 그 승인 규칙에 맞는 추가 비교 테스트를 수행한다.
4. 신경 조종을 선택한 뒤 동일 입력 시간의 이동 거리, 방향 반전 최대 스텝, 카메라 중심, 충돌을 선택 전후 비교한다.
5. 포유류 적응 전후 지정 통로를 각각 시도해 해당 통로만 잠금 해제되는지 확인한다.
6. 백혈구 접촉 0회와 1회 이상 성공 경로를 비교해 복귀 면역값에 포착 누적이 정확히 반영되는지 확인한다.
7. 실패 경로 직후 변이 목록과 세 효과가 모두 이전 상태 그대로인지 확인한다.
8. 성공 루프를 반복해 기존 획득 변이 유지, 새 선택 적용, 내부 상태 초기화가 서로 섞이지 않는지 확인한다.
9. 처음 시작부터 변이 적용 후 2D 쥐 복귀까지 설명 없는 플레이테스트를 하고 다섯 가지 이해 질문을 확인한다.
10. EditMode·최소 PlayMode·Unity MCP Play·Windows 빌드 및 실행본에서 성공·실패 전체 루프를 검증한다.

### 제외 범위

- 네 번째 이상 변이
- 변이 등급·랜덤 희귀도·리롤
- 숙주 경험 특성 계승
- 다중 숙주 전이

- 잠복 강화의 위험 행동 상승 억제 효과 신설

- 선행: 2단계의 성공 `MutationSelection` 인계와 실패 무보상 복귀

- 차단 조건: 다중 변이 적용, 실패 보상 발생, 변이 효과 미체감, 복귀 후 이전 모드 입력·충돌 잔존

## 6. 단계 간 공통 회귀 보호

각 단계는 해당 단계의 신규 테스트만 통과해서는 완료로 보지 않는다. 아래 묶음을 누적 실행한다.

1. 기존 순수 상태 EditMode 테스트
2. 기존 3D 쥐 숙주 핵심 상태·성공·실패 회귀 테스트
3. 완료된 2D 기술 샘플의 이동·충돌·카메라·Y 정렬 테스트
4. 해당 단계의 신규 상태·씬 계약 테스트
5. Unity MCP Play의 모드/HUD/입력/Console 점검
6. 단계별 임시 Windows 빌드 성공
7. 3단계에서는 Windows 실행본 성공·실패 전체 루프 플레이

특히 다음 불변식을 보호한다.

- 한 시점에 입력 가능한 게임 모드는 하나다.
- 면역 100% 전환, 성공, 실패, 변이 선택은 각각 한 번만 발행된다.
- 물리 위치는 시각 프레임·카메라 스냅·Y 정렬 때문에 바뀌지 않는다.
- 모드 전환 후 이전 모드의 입력, Trigger, UI, 충돌은 세션을 변경하지 않는다.
- 실패는 변이를 지급하지 않는다.
- 성공 복귀는 선택 변이와 내부 포착 부담을 모두 반영한다.
- 기존 3D 씬과 기술 샘플은 별도 승인 전까지 비교·회귀 기준으로 남는다.

## 7. 씬과 보존 시점에 대한 루프 관점 제안

### 추천

- `RatHost2DTechnicalSample.unity`는 기술 회귀 기준으로 보존한다.
- 실제 핵심 루프는 별도 `RatHost2DPrototype.unity` 같은 프로토타입 씬에서 단계적으로 구성한다.
- 기술 샘플에서 수용된 알고리즘과 동작 계약은 공용 2D 런타임 계층 또는 명시적 어댑터로 재사용한다.
- 기존 `RatHostPrototype.unity` 3D 씬은 3단계 전체 루프의 Windows 실행본 수용과 회귀 대조 완료 전까지 유지한다.
- 3단계 완료 후에도 즉시 삭제하지 말고, 사용자가 2D 씬을 공식 프로토타입 기준으로 승격한다고 승인한 별도 정리 작업에서 Build Settings·레거시 보존 방식을 결정한다.

### 이유

- 기술 샘플을 직접 확장하면 이동·카메라·충돌 기준과 실제 루프 결합 문제가 섞인다.
- 별도 2D 프로토타입 씬은 기술 기준을 고정한 채 단계별로 상태·콘텐츠를 추가할 수 있다.
- 기존 3D 씬은 상태 규칙과 성공·실패·변이 효과를 대조할 실제 회귀 기준이다.

## 9. 범위 초과 여부

이 검토안은 승인된 쥐 숙주 1차 프로토타입의 최소 루프 안에 있다. 다음 항목은 제안하지 않는다.

- 벌레 튜토리얼
- 여러 숙주 전이 체인
- 인간 숙주
- 병원·연구소·백신
- 엔딩
- 영구 성장
- 완성형 로그라이크
- 최종 아트 확정

문서 작성 과정에서 Unity 코드, 씬, 테스트, ProjectSettings, 패키지, 아트 에셋은 변경하지 않았다.
