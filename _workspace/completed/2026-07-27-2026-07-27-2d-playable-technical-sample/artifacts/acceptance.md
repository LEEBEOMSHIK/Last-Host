# 2D 플레이어블 기술 샘플 수용 기준

## 루프 단계와 범위

- 대상 루프: `쥐 숙주 조종 → 작은 하수도 방 탐험`의 기술 성립 여부.
- 포함: 화면 기준 WASD, 2D 이동·충돌, 방향 표시, 카메라 추적, Y 정렬·가림, 최소 HUD.
- 제외: 면역 경계도 100% 전환, 내부 바이러스 미니게임, 변이 조각·선택·복귀를 포함한 핵심 루프 전체 이관.
- 산출물 성격: 2D 전환을 판정하기 위한 기술 샘플이며 최종 타일·스프라이트·게임 규격이 아니다.
- 레거시 경계: 기존 `RatHostPrototype` 3D 씬·코드·에셋을 수정하거나 대체하지 않는다.

## 시험 기준값과 공통 허용 오차

| 항목 | 시험값 |
| --- | --- |
| 기준 화면 | `960×540`, 16:9 |
| 확대 확인 | `1920×1080`, 16:9 |
| 아이소메트릭 셀 후보 | `64×32 px` |
| PPU 후보 | `64` |
| 카메라 스냅 단위 | `1/64 = 0.015625` world unit |
| 입력 벡터 최대 크기 | `1.0` |
| 대각선/직선 속도 비 | `0.99~1.01` |
| idle 위치 드리프트 | `≤ 0.0001` world unit / 300 FixedUpdate |
| 카메라-쥐 중심 XY 거리 | `≤ 0.0112` world unit |
| 화면 중심 오차 | X·Y 각각 `≤ 0.5` logical pixel |
| 방향 전환 시 1스텝 최대 이동 | `moveSpeed × fixedDeltaTime × 1.05 + 0.0001` |
| 충돌 허용 침투 | Physics2D signed distance `≥ -0.001` world unit |

카메라 중심은 `Camera`의 XY 중심과 쥐의 명시적 follow target 사이 거리로 계산하며 Z축은 제외한다. 화면 중심 오차는 `960×540` 논리 화면에서 `WorldToScreenPoint(followTarget)`과 `(480,270)`의 차이다.

## 기능 계약

### 입력

| ID | 수용 기준 |
| --- | --- |
| IN-01 | `W/S/A/D`는 각각 화면 위/아래/왼쪽/오른쪽으로 이동한다. 1초 이동 후 화면 변위와 목표 단위축의 dot product는 `≥ 0.999`, 직교축 변위 비율은 `≤ 0.01`이다. |
| IN-02 | 네 대각선 입력은 `(±1,±1).normalized`로 처리한다. 정규화 후 벡터 크기는 `1.0 ± 0.001`이고 같은 시간의 대각선/직선 이동거리 비는 `0.99~1.01`이다. |
| IN-03 | 반대 입력 `A+D`, `W+S`는 해당 축을 `0`으로 상쇄한다. 네 키를 모두 누르면 최종 이동 벡터는 `(0,0)`이다. |
| IN-04 | 입력이 없으면 최종 이동 벡터는 매 FixedUpdate에서 정확히 `(0,0)`이며 마지막 방향 표시는 유지할 수 있지만 위치는 변하지 않는다. |
| IN-05 | 방향 변경은 현재 위치를 기준으로 다음 물리 스텝부터 적용한다. 입력 변경이 위치·카메라·애니메이션 위상을 초기 위치로 재설정하지 않는다. |

### 처리

| ID | 수용 기준 |
| --- | --- |
| PR-01 | 쥐 이동 루트에는 `Rigidbody2D`와 `Collider2D`가 존재한다. 플레이 중 위치 변경은 물리 스텝과 승인된 이동 API를 통하며 방향 표시 자식은 물리 루트 위치를 쓰지 않는다. |
| PR-02 | 직선 100 FixedUpdate와 대각선 100 FixedUpdate의 평균 속도 차이는 `≤ 1%`다. 각 스텝 변위는 `moveSpeed × fixedDeltaTime × 1.05 + 0.0001`을 넘지 않는다. |
| PR-03 | `D→A`, `A→D`, `W→S`, `S→W`를 각각 30 FixedUpdate씩 연속 전환해도 전환 직후 스텝 변위는 PR-02 한도 이하다. 현재 위치와 무관한 점프, 누적 오프셋, 원점 복귀는 `0건`이다. |
| PR-04 | 무입력 300 FixedUpdate 동안 쥐 물리 루트의 시작-종료 XY 거리는 `≤ 0.0001`, `Rigidbody2D.linearVelocity` 크기는 각 스텝 `≤ 0.0001`이다. |
| PR-05 | 벽 또는 수로 Collider를 향해 120 FixedUpdate 입력해도 Collider signed distance는 `≥ -0.001`이며, 마지막 60스텝의 벽 법선 방향 누적 이동은 `≤ 1/64` world unit이다. 접선 방향 미끄러짐은 허용한다. |
| PR-06 | 카메라는 각 `LateUpdate` 종료 시 쥐 follow target을 `1/64` world unit 격자에 맞춘다. 중심 XY 거리는 `≤ 0.0112`, X·Y 화면 오차는 각각 `≤ 0.5` logical pixel이다. |
| PR-07 | 쥐가 이동·정지·충돌 중이어도 PR-06 기준을 연속 300 렌더 프레임 동안 만족한다. 카메라와 쥐가 서로 다른 기준 위치를 누적하는 프레임은 `0건`이다. |
| PR-08 | 정렬 기준은 스프라이트 중심이 아니라 명시된 발 접지점 Y다. 발 Y가 `1/64` 이상 화면 아래인 객체는 화면 위 객체보다 높은 `sortingOrder`를 가진다. |
| PR-09 | 쥐가 소품의 가림 기준 Y를 한 번 통과하면 앞/뒤 관계가 정확히 `1회` 전환된다. 경계 왕복 없이 같은 위치에서 300프레임 정지할 때 `sortingOrder` 변경은 `0회`다. |

### 출력

| ID | 수용 기준 |
| --- | --- |
| OUT-01 | 8개 이동 방향 각각에 대응하는 표시 방향이 존재하며, 입력 방향 변경 후 늦어도 다음 렌더 프레임에 갱신된다. 방향 표시 변경만으로 물리 루트 위치가 `0.0001` world unit 이상 변하지 않는다. |
| OUT-02 | 벽·수로 충돌 시 쥐는 통과하지 않고, 허용된 접선 이동 또는 정지로 보인다. Collider와 화면 스프라이트의 접지점 차이 때문에 벽 안쪽으로 보이는 프레임은 허용하지 않는다. |
| OUT-03 | 쥐가 소품 뒤에 있을 때 쥐의 `sortingOrder`가 소품보다 낮고, 앞에 있을 때 높다. 동일 입력을 3회 반복해도 결과 순서는 매회 동일하다. |
| OUT-04 | `960×540`과 `1920×1080`에서 쥐, 통행 가능 바닥, 충돌 벽·수로, 앞뒤 정렬 소품을 서로 구분할 수 있다. 플레이어 중심은 HUD에 가리지 않는다. |
| OUT-05 | 자동 계측은 최소한 쥐 위치, FixedUpdate 최대 스텝 변위, 카메라 중심 오차, 현재 방향, 현재 sorting order를 테스트 결과 또는 `Player.log`에 남긴다. |

## 기존 3D 비변경 기준

1. 구현 전 `UnityProject/Assets/_Project/Scenes/RatHostPrototype.unity`와 기존 3D 관련 파일의 SHA-256 기준 목록을 기록한다.
2. 구현 후 같은 목록의 해시 불일치는 `0건`이어야 한다.
3. `git diff --name-only`에서 기존 `RatHostPrototype.unity`와 기존 3D 코드·에셋의 수정·삭제는 `0건`이어야 한다.
4. 새 2D 샘플은 별도 씬·코드·에셋 경로에만 추가한다.
5. 신규 패키지, Unity/URP 버전, 기존 Build Settings의 파괴적 교체는 `0건`이어야 한다.
6. 사용자 로컬 `ProjectSettings.asset`의 `APP_UI_EDITOR_ONLY`, `_workspace/previews/`, 기존 `Builds/`를 변경하지 않는다.

## Unity MCP Play 테스트 시나리오

1. `RatHost2DTechnicalSample` 씬을 열고 예상 루트·카메라·HUD가 활성인지 확인한다.
2. Play 진입 후 5초간 무입력 상태를 유지한다. 시작/종료 위치 차이 `≤ 0.0001`, 카메라 중심 오차 X·Y 각각 `≤ 0.5 logical px`여야 한다.
3. `W`, `A`, `S`, `D`를 각각 1초 이상 입력한다. 각 화면 방향 dot product `≥ 0.999`, 대각선이 아닌 축의 변위 비 `≤ 0.01`을 기록한다.
4. `W+D`, `W+A`, `S+D`, `S+A`를 각각 1초 이상 입력한다. 같은 시간 직선 대비 이동거리 비가 각각 `0.99~1.01`이어야 한다.
5. `D→A`와 `W→S`를 키 해제 공백 없이 전환한다. 최대 1스텝 변위가 PR-02 한도 이하고 순간이동 `0건`이어야 한다.
6. 벽과 수로를 향해 각각 2초 이상 입력한다. 관통 `0건`, signed distance `≥ -0.001`, 카메라 중심 기준 유지 여부를 기록한다.
7. 쥐를 정렬 소품의 뒤→앞→뒤로 이동시킨다. 각 교차에서 앞뒤 관계가 1회씩만 바뀌고 정지 중 깜빡임 `0건`인지 확인한다.
8. `960×540` Game View에서 HUD 4종, 쥐·바닥·벽·수로·소품 가독성과 중앙 비가림을 확인한다.
9. Console의 이번 샘플 관련 Error·Exception·Assert는 `0`, Warning은 `0`을 목표로 하며 남은 Warning은 원인과 비영향 근거가 있어야 한다.
10. Play를 종료하고 씬 dirty 변경 `0건`, 기존 3D 씬·파일 변경 `0건`을 확인한다.

MCP가 실제 키 입력을 전달하지 못하면 동일 Input Action을 통과하는 검증 전용 입력 주입을 사용할 수 있다. Transform 직접 이동은 대체 검증으로 인정하지 않는다. 실제 입력 또는 같은 Input Action 경로를 검증하지 못한 항목은 `미검증`으로 남기며 MCP Play 통과를 주장하지 않는다.

MCP 기록에는 단계별 쥐 world XY, 최대 FixedUpdate 변위, 카메라 XY 거리·logical pixel 오차, 방향, sorting order, Console 집계를 남긴다.

## Windows 임시 빌드 테스트 시나리오

1. 샘플 씬만 명시한 임시 Windows x86_64 빌드를 저장소 밖 또는 승인된 임시 경로에 생성한다. 빌드 프로세스 exit code `0`, 실행 파일과 Data 폴더 존재, BuildReport 실패 `0건`이어야 한다.
2. `960×540` windowed로 실행하고 5초 idle, 4방향, 4대각선, `D→A`, `W→S`, 벽·수로 충돌, 소품 앞뒤 교차를 순서대로 수행한다.
3. 같은 빌드를 `1920×1080` 16:9로 다시 실행해 쥐·환경·HUD 가독성, 화면 중심 오차와 HUD 앵커를 확인한다.
4. 두 실행 모두 idle 드리프트 `≤ 0.0001`, 대각선/직선 거리 비 `0.99~1.01`, 방향 전환 최대 스텝 PR-02 이내, 충돌 관통 `0건`, 카메라 중심 오차 X·Y 각각 `≤ 0.5 logical px`여야 한다.
5. 빌드의 자동 진단 요약 또는 `Player.log`에 OUT-05 계측값과 각 시나리오 pass/fail을 남긴다.
6. 두 실행의 `Player.log`에서 이번 샘플 관련 Error·Exception·Assert `0건`을 확인하고, 정상 종료 exit code `0`을 기록한다.
7. 임시 빌드가 기존 `Builds/`나 기존 Windows 플레이어를 덮어쓰지 않았음을 확인한다.

Windows 빌드 성공과 Windows 플레이 통과는 분리해 판정한다. 빌드만 생성하고 실행하지 못했거나 실제 키 입력·화면·로그를 확인하지 못하면 `빌드 성공 / 플레이 미검증`으로 기록하며 Windows 플레이 통과를 주장하지 않는다.
