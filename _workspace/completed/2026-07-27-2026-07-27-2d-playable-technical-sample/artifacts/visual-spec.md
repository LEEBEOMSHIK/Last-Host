# 2D 플레이어블 기술 샘플 비주얼 규격

## 비주얼 판단

이 문서는 `RatHost2DTechnicalSample`의 기술 성립 여부를 확인하기 위한 시험 규격이다. `960×540`, 아이소메트릭 셀 `64×32 px`, `PPU 64`는 모두 **사용자 수용 전 시험값**이며 최종 제품 규격이 아니다.

목표는 목업을 그대로 복제하는 것이 아니라 다음 네 가지를 실제 Unity 플레이에서 확인하는 것이다.

1. 공통 픽셀 격자의 반복 타일과 자연형 쥐가 한 화면에서 어울리는가?
2. 이동·카메라 추적 중 픽셀이 흔들리거나 흐려지지 않는가?
3. 벽·수로 충돌과 소품 앞뒤 정렬이 시각적으로 납득되는가?
4. 작은 실제 표시 크기에서도 쥐, 통행 가능 바닥, 위험 수로와 HUD가 즉시 구분되는가?

## 시험값과 장단점

| 항목 | 시험값 | 장점 | 위험·한계 | 이번 샘플의 판정 기준 |
| --- | --- | --- | --- | --- |
| 내부 기준 화면 | `960×540`, 16:9 | `1920×1080`에서 정확히 2배 확대 가능. 목업의 환경 밀도와 자연형 쥐 디테일을 비교하기 좋음 | 낮은 내부 해상도보다 도트가 덜 굵고 제작 픽셀 수가 많음. `1600×900`, `1366×768` 등은 비정수 확대 문제 발생 가능 | 우선 `960×540`와 `1920×1080 2×`를 통과. 비정수 화면은 정수 확대+레터박스 또는 별도 후속 정책으로 분리 |
| 아이소메트릭 셀 | `64×32 px` | 표준적인 2:1 다이아몬드로 방향과 반복 경계를 읽기 쉬움. PPU64에서 월드 `1×0.5 unit`으로 계산 가능 | 화면 폭에 약 15개 셀만 보여 시야가 좁을 수 있음. 벽·수로 변형 수가 늘면 제작량 증가 | 타일 모서리, 줄눈, 수로 경계가 반복 시 끊기지 않고 걷기 가능/불가가 즉시 구분 |
| Pixels Per Unit | `64` | 64px 타일 폭이 정확히 1 world unit. `1/64 unit` 카메라 스냅과 계산이 단순 | 세로 셀은 0.5 unit이므로 그리드·충돌 좌표를 임의로 혼용하면 반 칸 오차 발생 | 아트 PPU를 전부 64로 통일하고 논리 충돌 데이터와 시각 타일의 원점을 문서화 |
| 카메라 스냅 | `1/64 world unit` | Point 샘플링에서 이동 중 픽셀 떨림을 억제 | 플레이어 루트까지 양자화하면 조작이 계단식으로 보일 수 있음 | 플레이어 이동값은 연속으로 유지하고, 최종 추적 카메라 위치만 렌더 직전에 스냅 |
| 월드 카메라 높이 | `540 / 64 = 8.4375 unit` | 기준 화면과 PPU에서 수직 표시 범위가 명확 | 반정수 값이므로 임의 반올림 시 화면 크기가 달라짐 | 직교 카메라 기준 `orthographicSize = 4.21875` 후보로 시작하고 실제 프레이밍 기록 |

### 규격 승격 전 반드시 비교할 대안

- 더 굵은 도트와 낮은 제작량이 필요하면 `480×270` 내부 화면을 후속 비교한다.
- 더 넓은 시야가 필요하면 카메라 확대보다 `48×24` 또는 다른 타일 규격을 별도 비교한다.
- `960×540 / 64×32 / PPU64` 중 하나만 바꾸지 말고 화면 점유율·카메라·충돌·쥐 크기를 함께 비교한다.

## 기술 플레이스홀더 공통 팔레트

- 전체 장면은 투명색을 제외하고 **공용 16~20색 이내**를 목표로 한다.
- 각 대상은 최소 3단계인 `깊은 그림자 / 기본색 / 선택 하이라이트`를 사용한다.
- 광원 방향은 목업처럼 화면 좌상단 또는 상단 한 방향으로 통일하되, 이번 샘플에서는 동적 2D 조명을 필수로 하지 않는다.
- 반투명 디더·안티앨리어싱을 사용하지 않는다. 가장자리는 이진 알파로 만든다.
- 색은 최종 팔레트가 아니라 통행 가능 바닥, 막힌 벽, 위험 수로, 플레이어, 소품을 구분하는 기술 표식이다.

## 환경 플레이스홀더

### 바닥

- [ ] 셀 크기: `64×32 px`, 투명 모서리를 가진 2:1 다이아몬드.
- [ ] 최소 색: 4색 — 줄눈/깊은 그림자, 바닥 기본, 중간 밝기, 젖은 하이라이트.
- [ ] 다이아몬드 네 모서리의 연결 픽셀이 인접 타일과 정확히 이어진다.
- [ ] 통행 가능 영역은 벽·수로보다 중간 명도로 유지한다.
- [ ] 기본 반복 타일 1종으로 경계를 먼저 검증하고, 장식 변형은 기술 통과 후 추가한다.

### 벽

- [ ] 최소 구성: `64×32` 상단 면 + `32 px` 높이의 전면 면 또는 같은 효과의 분리 스프라이트.
- [ ] 최소 색: 5색 — 최심부, 전면 그림자, 벽 기본, 상단 기본, 가장자리 하이라이트.
- [ ] 벽 상단과 전면은 통행 불가 실루엣이 바닥보다 먼저 읽힌다.
- [ ] 충돌체는 픽셀 외곽이 아니라 논리 그리드 경계를 사용한다.
- [ ] 캐릭터가 벽 뒤로 들어갈 수 있는 구간은 `후면/전면 가림 레이어`를 분리한다.

### 수로

- [ ] 셀 기반 경계는 `64×32 px` 투시와 일치한다.
- [ ] 최소 색: 4색 — 깊은 물, 물 기본, 반사, 경계 거품/빛.
- [ ] 바닥보다 어둡거나 색상이 분명히 달라 통행 불가·위험 영역으로 읽힌다.
- [ ] 물결은 타일 경계에서 끊기지 않으며, 애니메이션이 없어도 수로로 식별된다.
- [ ] 실제 충돌은 별도 2D Collider로 처리하고 물 픽셀과 정확히 같다고 가정하지 않는다.

### 소품

- [ ] 최소 소품: 상자 또는 통 1종, 배수구/파이프 입구 1종.
- [ ] 대상당 4~5색 이내로 하고 배경보다 대비를 높이지 않는다.
- [ ] 캔버스 후보: `64×64 px`, 실제 실루엣은 한 셀 폭 안에서 유지한다.
- [ ] 피벗은 지면 접촉 중심에 두며, 스프라이트의 시각 중심을 피벗으로 사용하지 않는다.
- [ ] 캐릭터가 소품 위·아래를 통과할 때 발 접지점 기준으로 앞뒤가 한 번만 바뀐다.

## 자연형 쥐 플레이스홀더

### 최소 실루엣

- [ ] 프레임 캔버스 후보: `64×64 px`, PPU64.
- [ ] 측면 방향의 실제 불투명 실루엣은 폭 `48~56 px`, 높이 `24~32 px` 안에서 시작한다.
- [ ] 등–목–머리가 끊긴 구체 조립처럼 보이지 않고 하나의 낮은 곡선으로 이어진다.
- [ ] 코 방향, 둥근 귀 2개, 가슴·뒷다리 질량, 가는 꼬리 시작점이 실제 표시 크기에서 읽힌다.
- [ ] 정면·후면은 측면보다 폭이 자연스럽게 좁아질 수 있으나 몸통 길이감, 머리 크기, 귀 간격과 접지 높이는 같은 개체로 유지한다.
- [ ] 털은 개별 선이 아니라 2~4px 단위의 명암 군집으로만 암시한다.
- [ ] 수염은 가독성에 도움을 주는 방향에서만 제한하며 1px 노이즈가 되면 생략한다.

### 최소 색

투명색을 제외한 **8색**을 기본으로 한다.

1. 외곽/최심부 그림자
2. 털 그림자
3. 털 기본색
4. 털 하이라이트
5. 귀·발·꼬리 그림자
6. 귀·발·꼬리 기본색
7. 눈·코의 짙은 색
8. 눈 하이라이트 또는 선택된 밝은 접지 픽셀

- [ ] 배경과 겹칠 때 실루엣이 사라지면 전체 외곽선을 두껍게 하기보다 접지 그림자 또는 배경 대비를 먼저 조정한다.
- [ ] 목업 쥐의 갈색·분홍 계열은 참고하되 색값을 최종 팔레트로 선언하지 않는다.

### 피벗과 캔버스

- [ ] 모든 방향·프레임에 같은 `64×64 px` 캔버스와 PPU64를 사용한다.
- [ ] 발 접지선 후보는 캔버스 아래에서 `10~12 px` 위에 둔다.
- [ ] Custom Pivot 후보는 발 접지 중심 `(0.5, 0.1875)`이며, 접지선이 12px일 때의 시험값이다.
- [ ] 꼬리가 캔버스 밖으로 잘리지 않도록 실루엣을 이동하되 프레임마다 피벗을 움직이지 않는다.
- [ ] Animator 프레임 교체가 논리 Transform, Collider, 상호작용 원점을 바꾸지 않는다.

### 8방향 × 2프레임

- 방향 순서는 기존 프로젝트 호환성을 위해 `S, SW, W, NW, N, NE, E, SE`로 고정한다.
- 각 방향은 `walk-a`, `walk-b` 2프레임을 가진다. 총 최소 산출물은 16프레임이다.
- `walk-a`와 `walk-b`는 대각선 다리쌍의 지지/전진 관계를 교대하고 몸통 위치는 고정한다.
- 대기는 해당 방향의 `walk-a`를 정지 표시로 사용할 수 있으나 재생하지 않는다.
- 시험 재생 속도 후보는 `6 fps`이며 이동 속도와의 발 미끄러짐은 QA에서 관찰한다.

체크리스트:

- [ ] 8방향 모두 코가 해당 이동 방향을 명확히 가리킨다.
- [ ] 방향 전환 시 몸통 크기, 눈·귀·코, 꼬리 길이와 명암 방향이 바뀌지 않는다.
- [ ] 두 프레임 사이에 root 수직 튐, 캔버스 이동, 피벗 이동이 없다.
- [ ] `walk-b → walk-a` 반복 이음새에서 실루엣 팝이 없다.
- [ ] 좌우 반전은 기술 플레이스홀더에서만 허용하며, 광원·비대칭 무늬·꼬리 방향이 어색하면 8방향 개별 프레임으로 교체한다.

## Sprite Import와 픽셀 출력

모든 월드 타일·캐릭터·소품에 다음을 적용한다.

- [ ] Texture Type: `Sprite (2D and UI)`
- [ ] Pixels Per Unit: `64`
- [ ] Filter Mode: `Point (no filter)`
- [ ] Generate Mip Maps: `Off`
- [ ] Compression: `None`
- [ ] Wrap Mode: `Clamp`
- [ ] Mesh Type: `Full Rect`
- [ ] 알파: 이진 알파, 가장자리 반투명 픽셀 없음
- [ ] Sprite Atlas: 기술 샘플에서는 사용하지 않음. 필요 시 회전·Tight Packing 금지와 충분한 padding을 별도 검증

카메라:

- [ ] 기준 내부 화면은 `960×540`.
- [ ] PPU64 기준 직교 크기 후보는 `4.21875`.
- [ ] 플레이어의 연속 위치를 추적한 뒤 최종 카메라 위치만 `1/64 unit`으로 스냅한다.
- [ ] X/Y 스냅은 같은 프레임 단계에서 한 번만 수행한다.
- [ ] 정지, 느린 이동, 대각 이동에서 타일 줄눈과 쥐 외곽선이 1px 왕복하지 않는다.
- [ ] `1920×1080`은 Point 2× 확대 결과를 확인한다.
- [ ] 비정수 출력 해상도는 늘림으로 흐리게 만들지 않고 정수 배율+레터박스 또는 후속 정책 필요 상태로 기록한다.

## Y 정렬과 가림

정렬 기준은 스프라이트 bounds나 이미지 중심이 아니라 **논리 발 접지점의 world Y**다.

- 동적 대상의 기본식 후보:

```text
sortingOrder = layerBase - round(footWorldY * 100)
```

- `100`은 결정론적 순서를 위한 시험 배율이며 PPU와 동일한 값으로 오해하지 않는다.
- 같은 Y에서 순서가 흔들리지 않도록 대상 종류 또는 생성 순서가 아닌 명시적 tie-break 값을 사용한다.

체크리스트:

- [ ] 바닥·수로: 고정 배경 Sorting Layer.
- [ ] 벽 하단/전면 가림: 캐릭터를 덮을 수 있는 별도 레이어 또는 분리 스프라이트.
- [ ] 캐릭터·소품: 각 발 접지점 Y로 동적 정렬.
- [ ] 머리·꼬리 끝이 아니라 발 접지점이 같은 선을 넘을 때만 앞뒤가 바뀐다.
- [ ] 소품 위·아래 왕복 중 Sorting Order가 한 프레임에 여러 번 진동하지 않는다.
- [ ] 벽 뒤 통과, 아치, 큰 배관처럼 단일 Y 정렬로 해결되지 않는 곳은 전면 가림 스프라이트 또는 명시 영역으로 처리한다.
- [ ] Collider와 가림 경계가 달라도 충돌·표시가 모순되지 않는지 실제 이동으로 확인한다.

## HUD 분리

- HUD는 월드 Y 정렬과 카메라 스냅의 대상이 아닌 `Screen Space` 캔버스에 둔다.
- Canvas Scaler 기준 후보는 `960×540`이며 텍스트·선은 실제 출력에서 선명하게 유지한다.
- 최소 표시:
  - `2D TECHNICAL SAMPLE`
  - `WASD 이동`
  - `960×540 / Tile 64×32 / PPU64 — TRIAL`
  - 현재 방향과 Sorting Order 디버그 값
- HUD 아이콘과 배치는 목업을 복사하지 않는다. 시험값과 기술 상태를 읽히게 하는 디버그 UI다.

체크리스트:

- [ ] HUD는 벽·소품에 가려지지 않는다.
- [ ] 카메라 이동 중 HUD가 픽셀 스냅으로 흔들리지 않는다.
- [ ] 월드가 저해상도 타깃을 거쳐도 텍스트는 별도 선명 레이어로 읽힌다.
- [ ] `TRIAL` 또는 `PLACEHOLDER` 표기가 항상 보인다.

## 목업과 최종 에셋 경계

목업에서 가져오는 것:

- 자연스럽고 낮은 쥐 실루엣
- 조밀하지만 플레이 경로가 먼저 읽히는 환경
- 고정 아이소메트릭 시점
- 깊은 하수도 명암과 월드/HUD 분리

목업에서 자동으로 가져오지 않는 것:

- 정확한 맵 배치와 타일 투시
- 타일 크기, PPU, 스프라이트 셀 크기
- HUD 아이콘·게이지·수치
- 벽·수로 충돌과 가림 구조
- 개별 픽셀, 색상값, 생성 이미지의 쥐 프레임

완료 보고 경계:

- [ ] 기술 플레이스홀더를 최종 아트라고 부르지 않는다.
- [ ] 목업을 잘라 타일·쥐·HUD에 직접 사용하지 않는다.
- [ ] 16개 쥐 프레임은 방향·피벗·정렬 검증용이며 최종 캐릭터 품질 승인이 아니다.
- [ ] 시험값 통과는 `960×540 / 64×32 / PPU64`의 기술 후보 통과일 뿐 전체 프로젝트 규격 확정을 뜻하지 않는다.
- [ ] 최종 타일셋·쥐·소품·HUD 제작은 별도 자산 브리프, 사람 선별, 수작업 정리와 사용자 수용을 거친다.

## 구현 핸드오프 체크리스트

Unity 씬/통합 구현 담당:

- [ ] 바닥·벽·수로·소품·쥐 원본 파일과 Import 설정을 PPU64로 통일한다.
- [ ] 시각 타일과 Collider를 분리하고 64×32→1×0.5 unit 매핑을 기록한다.
- [ ] 쥐 논리 루트, Collider, 시각 자식, 발 접지 정렬점을 분리한다.
- [ ] 카메라만 최종 `1/64 unit` 스냅하고 플레이어 Transform을 강제로 양자화하지 않는다.
- [ ] HUD를 월드 렌더·Y 정렬에서 분리한다.

QA/검증 담당:

- [ ] `960×540` 정지 화면과 `1920×1080` 2× 화면을 캡처한다.
- [ ] 무입력, W/A/S/D, 대각 이동, 빠른 방향 반전에서 쥐·카메라 분리와 순간이동이 없는지 확인한다.
- [ ] 타일 반복 경계, Point 선명도, mipmap 없음, 1px 떨림을 확인한다.
- [ ] 바닥↔벽, 바닥↔수로 충돌 경계를 각 2회 왕복한다.
- [ ] 소품 위·아래와 벽 뒤 가림을 왕복해 정렬 팝·진동이 없는지 확인한다.
- [ ] 8방향 × 2프레임의 파일 수, 캔버스, PPU, 피벗, 명암과 체형 일관성을 대조한다.
- [ ] HUD가 월드와 독립적으로 선명하고 `TRIAL` 표기를 유지하는지 확인한다.
- [ ] 결과를 `통과 / 조정 필요 / 규격 대안 비교 필요`로 나누고 최종 규격 승인과 분리한다.

## 승인 필요

- 이번 문서의 값은 승인된 기술 샘플 안에서 구현·비교할 수 있다.
- 최종 내부 해상도, 타일 크기, PPU, 쥐 셀 크기, 팔레트, 프레임 수와 재생 속도의 프로젝트 공통 규격 승격은 사용자 화면·조작 수용 후 별도 승인한다.
- 신규 이미지 생성, 목업 편집, 최종 아트 제작은 이 산출물에 포함하지 않는다.
