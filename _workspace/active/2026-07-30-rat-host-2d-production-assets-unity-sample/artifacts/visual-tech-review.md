## blocker 수정 요구

### 1. HUD fill 레이어

- 붉은/청록 fill이 frame의 불투명한 내부 channel 아래에 가려지지 않도록
  렌더 순서를 수정한다.
- 수정 후 최소 다음 상태가 캡처에서 직접 보여야 한다.
  - 생명력 red full 또는 90%
  - 면역 teal half 또는 55%
- frame의 황동 외곽과 fill의 검은 분절선은 유지한다.

### 2. 카메라 프레이밍과 방 외곽

- 1920×1080 사용자 확인 캡처에서 이동 가능한 방이 화면 중심과 하단까지
  충분히 채워지게 한다.
- 단순 카메라 확대만으로 쥐·HUD를 더 크게 만들지 말고, 다음 중 기술
  샘플에 맞는 방법을 사용한다.
  - 바닥·수로 범위를 카메라 이동 여유까지 확장
  - 방 경계용 어두운 구조·전경 타일 배치
  - 카메라 bounds/confiner로 플레이 영역 밖의 순수 배경 노출 제한
- 목표: 방 밖의 순수 단색 여백이 화면의 주 구성으로 읽히지 않아야 한다.

## 비주얼 판단

실제 에셋의 재질·명암·자연형 쥐 품질은 Unity 반입 뒤에도 보존됐다.
따라서 아트 원본이나 PPU Import를 다시 낮은 품질로 대체할 이유는 없다.
문제는 Unity 조립의 HUD 레이어와 사용자 확인용 화면 구성이다.

## 목업과 실제 에셋 경계

목업의 전체 환경 밀도는 아직 전체 타일셋 범위이므로 이번 V1 한 방에서
완전히 재현할 수 없다. 하지만 검은 여백, 보이지 않는 상태 fill,
지나치게 강한 디버그 표기는 제한된 V1 범위와 별개의 화면 조립 문제다.
이 항목은 후속 전체 아트 확장으로 미루지 말고 현재 샘플에서 수정해야 한다.

## 타일·스프라이트 기준

- PPU 128과 0.5 논리 표시: 기술 후보로 유지 가능
- 환경 128×64, 쥐 256×192 공통 캔버스: 이번 반입에서 손상 없음
- 최종 PPU·HUD 화면 비율: blocker 수정 캡처의 사용자 판단 전 승격 금지
- 수로 edge/corner와 floor 변형 추가: V1 수용 뒤 환경 확장 작업에서 진행

## 플레이스홀더 기준

- 우상단 제목과 우하단 상태 문자열은 기술 디버그 표기로만 유지 가능
- 실제 PNG 환경·쥐·HUD를 다시 저밀도 플레이스홀더로 바꾸지 않는다.

## 승인 필요

- HUD fill과 카메라 프레이밍 수정 후 새 1920×1080 캡처를 다시 검토한다.
- 이후 사용자가 쥐·HUD 상대 크기와 PPU 128 후보를 최종 판단한다.
- 정지 캡처로 확인할 수 없는 상자·벽 앞뒤 전환은 QA Play 또는 사용자
  WASD 확인이 필요하다.

## 검증 방법

1. Unity MCP Main Camera 1920×1080 재캡처
2. bar 영역의 red/teal 상태 직접 확인
3. 단색 배경 노출과 방 화면 점유율 대조
4. 쥐 actual/50%/2× preview와 Game View의 픽셀 군집 대조
5. 쥐가 통·상자·벽의 앞과 뒤를 각각 통과하는 Play 캡처 대조

### 유지 항목

- PPU 128 후보와 nearest 50% 출력은 v1과 같은 선명도를 유지한다.
- clean/worn 바닥 경계에 새 seam, 알파 틈, 밝기 점프가 없다.
- 쥐의 낮고 긴 자연형 실루엣, 발 접지, 꼬리와 바닥 대비가 유지된다.
- 황동 HUD bevel과 red/teal 분절은 fill 수정 뒤에도 훼손되지 않았다.
- 현재 통 전면 가림은 시각적으로 자연스럽다.

### 남은 비차단 항목

- worn 바닥의 대각선 반복 주기는 넓어진 화면에서 더 잘 보인다.
- 수로 양측 embankment와 corner 변형이 부족해 목표 목업보다 수로 깊이가
  단순하다.
- 초상과 bar의 화면 점유율은 목표 목업보다 크다.
- 우상단 제목과 우하단 상태 문자열은 기술 디버그 표기다.
- 상자·벽의 양방향 가림 전환은 정지 캡처만으로 확정하지 않는다.

위 항목은 v2 기술 샘플 캡처의 blocker가 아니다. 전체 타일 변형과 정식
HUD 확장 범위, 실제 WASD Play 검증 또는 사용자의 상대 크기 판단에서
이어간다.
