# Production2D V1 가시 실루엣·가림 계약

## 판정

사용자 화면의 중앙 벽 겹침은 Rigidbody2D나 Collider2D가 서로 관통한 상태가 아니다. 쥐가 벽의 뒤쪽 접촉 위치까지 정상적으로 도달한 뒤, 벽의 단일 SpriteRenderer가 쥐의 긴 단일 SpriteRenderer 중앙만 가리면서 꼬리·발 또는 몸 일부가 분리되어 보이는 시각 가림 결함이다.

따라서 기존 `tieBreak=1` 정규화와 발밑 footprint 확대만 다시 조정해서는 완료 기준을 만족할 수 없다. 물리 접지와 가시 실루엣 가림을 분리하고, 뒤쪽 가림 중 쥐 한 장이 둘 이상의 보이는 조각으로 나뉘지 않게 하는 whole-character occlusion 계약이 필요하다.

## 화면 재현 대조

- 사용자 화면: `docs/references/images/image.png`
- 중앙 벽 템플릿 pivot: 약 `(496, 286)` screen px
- 쥐 중립 프레임 템플릿 root: 약 `(480, 273)` screen px
- 후보 출력은 `PPU 128`, display scale `0.5`이므로 쥐는 벽보다 월드 Y 약 `+0.20` 뒤에 있다.
- 중앙 벽 footprint는 root 기준 Y `-0.01 .. +0.17`, 쥐 footprint는 root 기준 Y `0 .. +0.26`이다. 뒤쪽 접촉에서는 쥐 root가 벽 root보다 약 `+0.17`에서 합법적으로 정지할 수 있다.
- 이때 벽 order는 `-74`, 쥐 order는 약 `-92`이므로 벽이 쥐보다 앞에 그려지는 관계 자체는 맞다.
- 문제는 그 앞뒤 관계 안에서 벽 alpha가 쥐 전체를 덮지 못해 한 쥐가 여러 조각처럼 보인다는 점이다.

## 실제 alpha 실루엣

측정 기준은 원본 PNG의 `alpha > 32`, 아래쪽이 Y `0`인 픽셀 좌표다.

| 대상 | 캔버스·pivot | 실제 alpha bounds(px) | pivot 기준 world bounds (`PPU 128`) |
| --- | --- | --- | --- |
| 쥐 neutral | `256×192`, `(128, 40)` | X `9..246`, Y `40..113` | X `-0.930..+0.922`, Y `0..+0.570` |
| 쥐 contact | `256×192`, `(128, 40)` | X `9..246`, Y `40..115` | X `-0.930..+0.922`, Y `0..+0.586` |
| 쥐 passing | `256×192`, `(128, 40)` | X `9..246`, Y `40..112` | X `-0.930..+0.922`, Y `0..+0.563` |
| 직선 벽 | `160×160`, `(80, 0)` | X `11..147`, Y `4..153` | X `-0.539..+0.523`, Y `+0.031..+1.195` |
| 통 | `96×112`, `(48, 0)` | X `13..81`, Y `2..107` | X `-0.273..+0.258`, Y `+0.016..+0.836` |
| 상자 | `112×112`, `(56, 0)` | X `9..101`, Y `2..107` | X `-0.367..+0.352`, Y `+0.016..+0.836` |

쥐 세 프레임의 공통 가시 폭은 `238px = 1.859 world`다. 현재 쥐 capsule은 size `(0.92, 0.26)`, offset `(0.08, 0.13)`이므로 X 범위가 root 기준 `-0.38..+0.54`뿐이다. 가시 실루엣 중 왼쪽 약 `70px`, 오른쪽 약 `49px`가 footprint 밖에 남는다.

두께가 `12px` 이상인 쥐의 몸통·머리 핵심 실루엣도 세 프레임에서 대략 X `-0.312..+0.891`이다. 현재 capsule은 오른쪽 핵심 몸통을 약 `0.35 world` 보호하지 못한다. flip 시 시각 몸통 방향은 뒤집히지만 capsule offset은 뒤집히지 않아 불일치 방향도 바뀐다.

직선 벽은 낮은 alpha 윤곽이 수평이 아니라 우하단에서 좌상단으로 기울어진다. 중앙 구간의 lower contour는 대략 `y(px) = -0.54*x_from_pivot + 35.9`이며, root 기준 X `-0.25 world`에서 보이는 벽 하단은 약 Y `+0.42 world`다. 현재 수평 BoxCollider 상단 `+0.17`과 약 `0.25 world` 차이가 나므로, 물리는 분리됐어도 쥐가 벽 그림 내부에 들어간 것처럼 보일 수 있다.

## 원인

1. `tieBreak=1`은 전환선을 `0.01 world`, 즉 `1.28 logical px`만 옮긴다. 이미 뒤쪽으로 분류된 쥐 한 장을 어떻게 가릴지는 해결하지 못한다.
2. 쥐의 충돌 footprint는 접지 몸통 기준이고, 가시 스프라이트는 꼬리까지 `1.859 world`로 매우 길다.
3. 벽·통·상자는 쥐보다 좁다. 쥐가 정면 뒤쪽에 서면 collider를 아무리 옆으로 넓혀도 오브젝트 양옆에 쥐 alpha가 남을 수 있다.
4. 모든 대상이 단일 SpriteRenderer다. 오브젝트가 앞인 순간 쥐 전체의 일부만 alpha 모양대로 가려지므로, 남은 꼬리·발·머리가 서로 떨어진 조각처럼 보인다.
5. 직선 벽의 실제 사선 접지 윤곽과 수평 BoxCollider·단일 고정 Y 정렬 기준도 일치하지 않는다.

## 권장 최소 구조

### 1. 물리 footprint와 가림 계약 분리

- 기존 발밑 collider는 이동 통로와 접지 감각을 위한 물리용으로 유지한다.
- 프레임별 실제 alpha AABB를 보수적으로 합친 쥐 가시 bounds를 별도 값으로 둔다.
  - X `-0.930..+0.922`
  - Y `0..+0.586`
- 각 occluder도 투명 캔버스 전체가 아니라 `alpha > 32`의 실제 bounds와 접지 윤곽을 사용한다.

### 2. whole-character occlusion

- 쥐 발점이 오브젝트 뒤이고 두 실제 alpha bounds가 겹치면 `occluded` 상태로 진입한다.
- 이 상태에서는 원본 쥐가 오브젝트 양옆·아래로 여러 조각으로 남지 않게 쥐 전체를 하나의 가림 단위로 처리한다.
- 현재 아트를 바꾸지 않는 최소 구현은 다음 중 하나다.
  1. 쥐 전체를 오브젝트 뒤에 숨기고 위치를 단일 작은 indicator/outline으로 표시한다.
  2. 오브젝트 내부 구간에만 이어지는 어두운 masked silhouette를 표시해 바깥의 쥐 alpha와 한 덩어리로 읽히게 한다.
- 단순한 renderer order 변경만으로 쥐를 전부 앞에 올리는 방식은 벽 위로 올라탄 것처럼 보이므로 사용하지 않는다.
- 단순 collider 확대만으로도 옆 접근은 줄일 수 있지만, 쥐보다 좁은 통·상자의 정면 뒤쪽 분리는 남으므로 최종 해결로 인정하지 않는다.

### 3. 안정적인 진입·해제

- 가림 진입과 해제에 최소 `2/128 = 0.015625 world` hysteresis를 둔다.
- 오브젝트 모서리에서 프레임별 bounds 차이와 pixel snap 때문에 매 프레임 상태가 뒤집히지 않게 한다.
- flip과 세 애니메이션 프레임 모두 동일한 보수 bounds 또는 프레임별 측정 bounds를 사용한다.

### 4. 벽 접지선

- 직선 벽은 수평 BoxCollider만으로 시각 접지선을 대표하지 않는다.
- 별도 사선 occlusion boundary 또는 alpha lower contour를 근사한 polygon/line을 사용해, 쥐 발점이 그 선의 앞인지 뒤인지 판정한다.
- 사용자 화면의 X 약 `-0.25 world` 지점에서는 wall root `+0.17`이 아니라 실제 lower contour 약 `+0.42`를 기준으로 앞뒤를 판정해야 한다.

## collider-only 보조값

측면 가시 겹침을 줄이는 보조 collider를 적용한다면 다음보다 작지 않아야 한다.

- 쥐 full-alpha shallow box: 폭 `240/128 = 1.875`, X offset 약 `-0.004`, 높이 `0.26`, Y offset `0.13`
- 직선 벽 폭: 최소 `140/128 = 1.094`
- 상자 폭: 최소 `96/128 = 0.750`
- 통 폭: 현재 `0.60` 유지 가능

이 값은 측면 접근만 보수화한다. 뒤쪽 정면에서 쥐가 오브젝트보다 넓어 생기는 분리는 해결하지 않으므로 whole-character occlusion을 대체하지 않는다.

## 수용 기준

1. `alpha > 32` 기준으로 neutral/contact/passing와 좌우 flip 전체에서 occluder가 쥐를 둘 이상의 가시 connected component로 나누지 않는다.
2. 노이즈를 제외하기 위해 분리 component 판정 최소 크기는 `4px`로 한다. `4px` 이상 떨어진 꼬리 끝·발·머리 조각은 0건이어야 한다.
3. 두께 `12px` 이상인 core body X `-0.312..+0.891`이 오브젝트 내부를 가로지르는 프레임은 0건이어야 한다.
4. 꼬리는 일부가 가려질 수 있지만, 본체와 끊긴 꼬리 끝이 `4px` 이상 독립적으로 보이면 실패다.
5. 진입·해제 hysteresis는 최소 `0.015625 world`이며, 같은 모서리를 10회 짧게 왕복할 때 상태 전환은 실제 경계 횡단당 최대 1회다.
6. 가림이 없는 측면 접촉의 alpha 경계 여유는 `1..2 logical px`, 즉 `0.0078125..0.015625 world`를 목표로 한다. `3px`를 넘는 눈에 띄는 빈틈은 실패다.
7. 벽·통·상자의 앞/뒤/좌/우 모서리를 실제 WASD로 통과하며, 쥐가 오브젝트 표면 위로 올라타 보이거나 한 프레임에서 양쪽으로 갈라지는 장면이 없어야 한다.
8. 정지·짧은 방향 반전에서 sorting/occlusion 상태 jitter가 0이어야 한다.

## 범위 판단

- 현 Production2D V1 side 3-frame 아트는 유지한다.
- 완전한 자연형 가림은 향후 8방향 아이소메트릭 쥐 스프라이트와 오브젝트별 전면/후면 레이어 제작에서 다시 검증해야 한다.
- 이번 결함 교정에서는 새 아트 없이 whole-character occlusion과 사선 접지선 판정으로 사용자 화면의 분리 현상을 제거하는 것이 최소 안전 범위다.
