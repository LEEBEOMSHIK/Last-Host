# 검증 기록

## 검증 대상

`docs/prototype/plans/rat-host-2d-art-production-roadmap.md`의 실제 2D 아트
제작 순서·기간·의존성·승인 게이트가 사용자 요청과 현재 프로젝트
출발점에 맞는지 독립 검증한다.

## 작업영역

- 로드맵 본문과 `docs/prototype/README.md` 색인
- 목표 reference README와 그래픽 방향 관리 기준
- 쥐 숙주 공식 범위와 AI 보조 아트 워크플로
- 작업 패킷·현황판·CURRENT의 상태 및 보호 경계

QA는 로드맵 원문을 수정하지 않았으며 발견 사항을 수정 요구로 남긴다.

## 실행한 검증

### 1. 사용자 요청과 현재 출발점 대조

명령:

- 로드맵의 자산 묶음·일정·승인 문구 검색
- 현재 `RatHost2DPrototype.unity`, Tile asset, 2D 이동·카메라·정렬
  스크립트, Stage1~3 런타임과 기존 쥐 시험 자산의 존재 확인

결과:

- 로드맵은 첫 샘플, 한 방 완성, 안정화 단계를 구분한다.
- 그러나 공식 기준선을 `전담 제작 라인 1개`의
  `후보 탐색 → 재제작 → Unity 반입 → QA` 전체 순차 작업으로만 잡아
  최종 안정화를 `30~50일`로 제시한다.
- 현재 저장소에는 이미 2D Tilemap, Floor/Wall/Water Tile asset,
  이동·충돌·픽셀 카메라·Y 정렬, Host/Internal/Mutation 루프와 원본
  `RatHost2DPrototype` 씬이 존재한다.

해석:

- 기존 플레이 가능한 씬에 실제 아트를 교체해 방향을 빠르게 검증하는
  경로와, 규격·자산을 넓게 신규 제작하는 보수 경로를 분리해야 한다.
- 현재 단일 `30~50일` 기준은 사용자가 묻는 “지금 출발점에서 첫 결과가
  언제 보이는가”에 과도하게 긴 답으로 받아들여질 수 있다.

수정 요구:

1. 기존 2D 씬·충돌·카메라·핵심 루프를 재사용하는 다음 누적
   `빠른 검증 트랙`을 별도 표로 추가한다.
   - 정적 후보: `0.5~1작업일`
   - 기존 씬 재사용 첫 플레이 샘플: `2~4작업일`
   - 한 방 기본 정리: `5~8작업일`
   - 쥐 8방향·핵심 효과 통합: `10~20작업일`
   - 시각 안정화: `15~30작업일`
2. 기존 `30~50일`은 타일 규격 재작업, 반복 변형, 쥐 전체 방향·프레임,
   UI·효과 완성도와 Windows 회귀까지 포함하는
   `신규 제작 전체/보수 상한 트랙`임을 명시한다.
3. 두 트랙 모두 고정 납기가 아니며 첫 실제 샘플 뒤 수정률로
   재산정한다는 문구를 유지한다.

### 2. 단계별 누적 작업일과 주차 산술

결과:

- G0 `2~3` + G1 추가 `3~5` = G1 누적 `5~8`: 일치
- G1 `5~8` + G2 추가 `0~2` = G2 누적 `5~10`: 일치
- G2 `5~10` + G3 추가 `10~15` = G3 누적 `15~25`: 일치
- G3 `15~25` + G4 추가 `5~10`은 `20~35`가 되어야 하나 문서는
  G4 누적 `20~30`으로 기재: 불일치
- 문서의 G4 `20~30` + G5 추가 `10~20` = G5 `30~50`: 일치
- 주 5작업일 기준 주차 표기는 각 누적 범위와 일치한다.

해석:

- G4의 추가 작업량 또는 누적 상한 중 하나가 잘못되었다.
- G4는 일정 판단의 핵심 구간이므로 현재 산술로는 승인할 수 없다.

수정 요구:

- `G4 누적 20~30일`을 유지하려면 `추가 5일`처럼 증분을 고치거나,
  `추가 5~10일`을 유지하려면 누적 `20~35일`과 후속 G5 범위를
  연쇄 수정한다.
- 바로 아래의 “G2 이후 추가 작업량 산식” 설명도 수정된 숫자와 같은
  규칙을 명확히 설명해야 한다.

### 3. 순차·2역할·3역할 일정

결과:

- 2역할 누적 증분
  `2~3`, `2~4`, `1~2`, `7~11`, `5`, `8~15`는 각 누적 범위와 일치한다.
- 3역할 누적 증분
  `2~3`, `2~3`, `1~2`, `5~9`, `5`, `7~13`도 각 누적 범위와 일치한다.
- 공통 규격·사용자 승인·Unity 통합은 단순 병렬화할 수 없다고
  명시했고 병렬안이 고정 납기가 아님을 반복해 오해를 막았다.

보완 요구:

- 3역할안의 `UI·Unity 반입·QA`에서 QA는 제작자 자체 점검을 뜻하는지
  명시하고, 루프 게이트의 독립 `QA/검증 에이전트` 판정은 별도로
  유지한다고 적어 역할 혼동을 막는다.

### 4. 자산 누락

결과:

- UI, 환경 타일, 소품, 쥐 8방향 정지·보행, 조명·효과,
  Unity 반입·QA의 선행 조건과 완료 증거가 표에 존재한다.
- 바이러스·백혈구·변이 조각도 1차 프로토타입 내부 화면 자산으로
  범위를 제한해 언급했다.

보완 요구:

- 바이러스·백혈구·변이 조각은 한 문장에만 묶여 있으므로 빠른/보수
  트랙 중 어느 게이트에서 최소 방향·상태 스프라이트와 피벗·충돌
  정합을 완료하는지 명시하면 누락 위험이 줄어든다.

### 5. 목업·imagegen 후보·실제 게임 에셋 경계

결과:

- AI 방향 이미지를 잘라 최종 애니메이션으로 쓰지 않는다고 명시했다.

판정: 통과.

## MCP 플레이 체크

실행하지 않았다.

사유:

- 이번 변경은 일정·범위 로드맵과 문서 색인뿐이며 Unity 플레이어블
  산출물을 변경하지 않는다.
- 작업 배정서가 Unity 코드·씬·ProjectSettings 변경과 실제 아트 생성을
  명시적으로 금지한다.
- 따라서 Unity Play·EditMode·Windows 빌드는 이번 문서 주장을
  증명하지 못하고 기존 작업 상태와 충돌할 위험만 있어 제외했다.

## 미검증 항목

- 실제 제작 속도: 첫 정적 후보와 기존 씬 재사용 샘플 전에는 실측 불가
- 사용자의 빠른 검증 트랙 범위·품질 수준 수용
- 최종 인력 수, 주당 실제 투입일, 피드백 대기시간

## 남은 위험

- 빠른 검증 트랙과 신규 제작 전체 트랙이 분리되지 않으면 사용자가
  첫 결과 시점과 전체 안정화 상한을 같은 납기로 오해할 수 있다.
- G4 산술 오류가 남으면 역할별 투입과 후속 계획의 기준이 흔들린다.
- 내부 미니게임 최소 아트의 제작 게이트가 암묵적이라 후반 누락될 수 있다.

### U0~U5 신규 제작 전체/보수 상한 산술과 조건
