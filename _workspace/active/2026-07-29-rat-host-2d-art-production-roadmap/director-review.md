## 근거

### 1. 사용자 피드백 일정 반영

로드맵 본문의 현재 기준은 기존 2D 구현을 재사용하는 빠른 검증 트랙이다.

```text
Q0 정적 후보                 0.5~1일
Q1 기존 씬 첫 플레이 샘플      2~4일
Q2 한 방 기본 정리             5~8일
Q3 8방향·핵심 효과 통합       10~20일
Q4 시각 회귀 안정화           15~30일
```

각 구간의 추가 작업량과 누적 하한·상한은 같은 규칙으로 맞는다. 이
일정은 현재 `RatHost2DPrototype`, Tilemap, 이동·충돌, 카메라, Y정렬,
Stage1~3 핵심 루프를 다시 만들지 않고 대표 아트를 교체하는 경우다.
고정 납기가 아니며 첫 `2~4일` 플레이 샘플의 실제 수정률로 재산정한다.

### 2. `30~50일`의 위치

`30~50일`은 현재 기본 일정이 아니다. 타일 변형, 높은 완성도의 쥐
8방향 정지·보행, UI·내부 자산·효과, 반복 수정과 Windows 빌드 회귀를
전담 한 라인이 폭넓게 순차 수행하는 `신규 제작 전체/보수 상한`이다.

U0~U5 산술도 다음과 같이 일치한다.

```text
2~3 → 5~8 → 5~10 → 15~25 → 20~30 → 30~50일
```

이전 U4 추가 `5~10일`과 누적 `20~30일`의 불일치는 추가 `5일`로
수정돼 해소됐다.

### 3. 프로젝트 방향과 범위

- 현재 방향인 2D 아이소메트릭 도트 타일·방향별 스프라이트를 유지한다.
- 목표 목업은 분위기·가독성 reference이며 실제 타일·스프라이트
  시트·애니메이션·충돌 데이터로 해석하지 않는다.
- 기존 2.5D·Blender·v5b는 레거시 비교 자료로만 남긴다.
- 작은 하수도 쥐 방, 쥐, 최소 내부 바이러스 자산, 변이 UI·효과로
  제한하며 인간·병원·백신·엔딩 등 프로토타입 밖 콘텐츠를 차단한다.
- 최종 PPU·타일·셀·프레임·조명 규격은 샘플과 사용자 수용 전에는
  확정하지 않는다.

범위 충돌은 없다.

### 4. 이미지 생성·실제 에셋·Unity 경계

이번 작업에서 생성된 파일은 Markdown 계획·색인·작업 기록뿐이다.
실제 래스터 이미지, 타일, 스프라이트, Unity Import, 코드, 씬,
ProjectSettings, 패키지는 생성하거나 변경하지 않았다.

로드맵은 다음 승인을 서로 분리한다.

1. imagegen 후보의 대상·개수·입력 reference·저장 위치
2. 사람 선별 뒤 수작업 게임 규격 재제작
3. 대표 방향 통과 뒤 쥐 8방향 정지·보행 확장
4. Sprite·Tile Import와 Unity 씬 적용
5. 첫 Unity 샘플 뒤 다음 묶음과 일정 재산정

AI 방향 이미지를 잘라 최종 애니메이션으로 쓰지 않고 생성 원본과 실제
게임 에셋의 경로·이력을 분리하는 기준도 유지한다.

### 5. Stage3 병행 상태

Stage3는 기술·운영 게이트와 총괄 검토를 통과했지만 사용자 실제
`1/2/3`·버튼·HUD·이동·전용 통로 수용을 기다리는 active 작업으로
상태판과 `CURRENT.md`에 보존돼 있다. 이 로드맵이 Stage3 사용자 수용을
완료로 바꾸거나 대체하지 않는다.

## QA/검증 기록 확인

QA 최종 판정 `완료 가능`의 근거는 충분하다.

- 빠른 트랙과 보수 상한 트랙의 증분·누적 산술 재검증
- 기존 2D 구현 재사용 출발점 확인

  짧은 보행·최소 HUD 제한 확인

QA가 최초 `수정 필요`를 내리고 수정본을 다시 검증한 이력도 분리돼 있어

## MCP 플레이 체크 확인

이번 작업은 문서 계획과 색인만 변경하며 Unity 플레이어블을 변경하지
않았다. QA가 Unity Play·EditMode·Windows 빌드·실제 이미지 생성을
실행하지 않은 사유를 명시했다. 이 작업의 완료 주장에는 추가 MCP
플레이 체크가 필요하지 않다.

## 1차 수정 요구 — 해소

로드맵 본문이 아니라 운영 기록의 최신 사실성을 보완해야 한다.

1. `task.md`의 수정 전 기준인 `1~2주 / 3~5주 / 6~10주`를 사용자
   피드백 이후 기준인 빠른 트랙과 `30~50일` 보수 상한 경계로
   갱신하거나, 최초 기준과 수정 이력을 명시적으로 분리한다.
2. `current-task-board.md`의 로드맵 행에 남은
   `담당 작성·QA 대기`, `1~2주 첫 샘플`, `6~10주 안정화`를
   QA 완료 및 빠른 트랙 기준으로 갱신한다.
3. `CURRENT.md`의 바로 이어서 할 작업에서 이미 끝난 담당 작성과 QA를
   제거하고 총괄 보완 재검토와 사용자 첫 묶음 승인 대기로 바꾼다.
4. 위 동기화 뒤 QA/검증 에이전트가 상태판·CURRENT·실제 경로·Git
   상태를 읽기 전용으로 짧게 재대조한다.

해당 운영 게이트는 아래 최종 재검토에서 해소를 확인했다.

- 첫 아트 샘플과 환경·쥐 V2·HUD 통합 제작 기준 작업은 사용자

- 두 완료 패킷의 필수 파일 5종이 존재하고 이전 active 경로 잔존은
  0개다.
- QA는 완료 보관, 공유 현황판, CURRENT와 이 active 로드맵 포인터,
  다음 승인 경계를 재대조해 `완료 가능`으로 판정했다.
- `HEAD = origin/main = 73c5750`이며 기존 Stage2·Stage3·
  ProjectSettings·preview 변경은 보호됐다.

현재 로드맵은 완료된 이미지 작업의 잔여 작업이 아니라 다음 실행을
통제하는 active 승인 포인터다. 따라서 지금 완료 보관하지 않고 실제
시험 재제작의 사용자 착수 승인을 기다린다.

### 다음 사용자 승인 항목

한 작업 패킷으로 다음 실제 게임 규격 시험 재제작의 착수를 승인받는다.

1. 기존 씬 교체를 전제로 한 반복 가능 환경 타일·대표 소품 샘플
2. 교정 쥐 V2를 기준으로 한 대표 3방향 정지와 짧은 2프레임 보행
3. 공통 bbox·투명 캔버스·발 피벗을 적용한 쥐 시험 시트
4. 투명 배경의 숙주 생명력·면역 경계도 HUD 모듈과 최소 상태

`960×540`, `64×32`, PPU `64`, 보행 2프레임은 시험값이며 최종
규격으로 확정하지 않는다. 전체 8방향·전체 보행 확장과 Unity 반입은
시험 결과를 사용자가 수용한 뒤 각각 별도 승인한다.
