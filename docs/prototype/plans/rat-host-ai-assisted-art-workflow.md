# 쥐 숙주 ChatGPT 이미지 연계 아트 작업 순서

## 목적과 문서 상태

이 문서는 2D 아이소메트릭 도트 방향에서 ChatGPT의 OpenAI 내장 `imagegen`을 목표 화면·콘셉트·래스터 후보 제작에 연결하는 절차를 정한다. 실제 생성은 사용자 승인 범위와 작업 패킷 안에서 수행한다.

생성 결과는 최종 타일셋, 방향별 스프라이트 시트, 애니메이션, 충돌 데이터 또는 Unity 적용 결과가 아니다. 사람 선별, 게임 규격 재제작, 일관성 QA와 Unity 검증을 거쳐야 한다.

우선 기준:

1. `../../design/visual/references/rat-host-2d-isometric-gameplay-mockup-v1.png`
2. `../../design/visual/references/README.md`
3. `../../design/visual/graphics-direction-management.md`
4. `../../design/visual/pixel-isometric-2d-production-guide.md`
5. 해당 `_workspace/active/<작업ID>/task.md`

## 도구와 역할 경계

- 이미지 생성은 가능한 경우 OpenAI 내장 `imagegen`을 우선한다.
- `ChatGPT 이미지 아트 에이전트`가 브리프 정제, 생성, 파일 저장, 생성 로그와 1차 일관성 점검을 담당한다.
- `비주얼/테크아트 에이전트`는 픽셀 규격·타일·캐릭터·정렬 관점에서 후보 적합성을 검토한다.
- 사용자는 목표 방향과 최종 후보를 선택한다.
- `QA/검증 에이전트`는 출처, 파일, 방향·프레임 일관성, 최종 게임 에셋과의 구분을 독립 대조한다.
- `Unity 씬/통합 구현 에이전트`는 별도 승인된 후속 작업에서만 Import와 씬 적용을 수행한다.

## 대상 자산 묶음

| 묶음 | imagegen으로 만들 수 있는 후보 | 실제 게임 에셋에서 다시 해야 할 일 |
| --- | --- | --- |
| 목표 화면 | 하수도 방, 조명, HUD가 포함된 게임플레이 목업 | 타일 분해, 화면 규격, 충돌, 정렬, HUD 구현 |
| 쥐 숙주 | 자연형 외형, 측면·정면·쿼터뷰 콘셉트, 색상안 | 같은 체형의 방향별 정지·보행 프레임, 공통 피벗, 투명 배경, 수작업 도트 정리 |
| 하수도 환경 | 바닥·벽·수로·배관의 스타일 보드와 타일 후보 | 반복 연결 타일, 변형 세트, 충돌·가림·정렬 데이터 |
| 내부 미니게임 | 바이러스·백혈구·변이 조각·HUD 후보 | 방향·상태 스프라이트, 애니메이션, 충돌과 UI 레이아웃 |
| UI | 게이지·슬롯·아이콘 스타일 후보 | 실제 수치 상태, 읽기 규격, 폰트와 9-slice 등 구현 자산 |

인간·병원·연구소·백신·캠페인·엔딩 등 승인 범위 밖 콘텐츠는 생성 브리프에도 추가하지 않는다.

## 7단계 작업 흐름

### 1. 생성 범위 승인

작업 패킷에 다음을 먼저 적는다.

- 자산 묶음과 화면 용도
- 후보 수
- 입력 reference
- 금지 요소
- 저장 위치
- 생성만 승인하는지, 후속 에셋 제작까지 승인하는지

한 단계의 승인이 다음 단계를 자동 승인하지 않는다.

### 2. 브리프와 일관성 시트

최소 항목:

- 시점과 카메라
- 대상의 화면 점유율
- 픽셀 밀도와 팔레트 분위기
- 실루엣과 유지할 특징
- 명암 방향
- 타일 반복 여부
- 방향·프레임 공통 요소
- 제외할 요소와 제3자 스타일 모사 금지

### 3. imagegen 후보 생성

프로젝트 reference와 승인된 브리프를 사용한다. 생성 직후 다음을 기록한다.

- 전체 프롬프트
- OpenAI 내장 `imagegen` 사용 사실
- 생성 날짜
- 입력 이미지 파일과 출처
- 출력 파일명·경로
- 후보 번호와 도구가 반환한 힌트

파일은 `_workspace/active/<작업ID>/artifacts/` 아래 목적별 폴더에 저장한다.

### 4. 1차 일관성 점검

전담 에이전트가 다음을 비교한다.

- 체형, 귀·눈·코·꼬리 길이
- 화면 점유율과 투시
- 팔레트와 광원
- 환경 타일의 경계와 반복 가능성
- 프레임·방향 사이의 임의 변형
- 원치 않는 글자·로고·오브젝트

문제가 있는 후보는 최종 선택 목록에서 제외하고 폐기 사유를 기록한다.

### 5. 사람 선별

비주얼/테크아트 에이전트가 게임 규격 관점에서 검토하고 사용자가 후보를 선택한다. 선택은 `목표 reference 채택`, `재생성`, `수작업 재제작 기준`, `폐기` 중 하나로 기록한다.

### 6. 실제 게임 에셋 재제작

승인된 후보를 참고해 반복 타일, 방향별 스프라이트, 애니메이션, 피벗과 투명 영역을 게임 규격으로 다시 만든다.

- AI 방향 이미지를 각각 잘라 최종 애니메이션으로 사용하지 않는다.
- 필요한 경우 AI 이미지를 가이드 레이어로 두고 수작업 도트 페인트오버·정리를 한다.
- 같은 체형과 접지점을 보장하는 일관성 시트를 유지한다.
- 생성 원본과 정리된 게임 에셋을 다른 경로와 이름으로 구분한다.

### 7. QA와 Unity 수용

별도 Unity 적용 승인 뒤 다음을 확인한다.

- Sprite Import와 픽셀 출력
- 방향·프레임 매핑
- 피벗과 충돌체 분리
- 이동·정지·방향 전환 안정성
- 타일 반복 경계
- 앞뒤 정렬과 가림
- 실제 Play와 Windows 빌드 가독성
- 생성 로그와 최종 파일 추적성

QA와 프로젝트 총괄 내부 판정 후 사용자가 최종 수용한다.
