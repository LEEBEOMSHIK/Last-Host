# 쥐 숙주 2D 실제 아트 제작 로드맵

## 문서 목적과 적용 범위

이 문서는 목표 화면
`docs/design/visual/references/rat-host-2d-isometric-gameplay-mockup-v1.png`의
분위기와 가독성을 쥐 숙주 1차 프로토타입의 실제 2D 아이소메트릭 게임
에셋으로 재구성하는 순서와 기간 가정, 승인 게이트를 정한다.

목업은 품질·분위기·구도 reference다. 반복 타일, 방향별 스프라이트,
애니메이션 프레임, 충돌·정렬 데이터 또는 최종 UI가 아니며 그대로
잘라서 게임에 사용하지 않는다.

## 비주얼 판단

- 목표는 `자연형 쥐`, `조밀하지만 이동 경로가 읽히는 하수도`,
  `고정 아이소메트릭 시점`, `명확한 깊이`, `최소 HUD`를 실제 플레이
  규격으로 재현하는 것이다.
- 화면 한 장의 유사도보다 타일 반복, 방향 전환 안정성, 발 접지 피벗,
  앞뒤 정렬, 실제 플레이 크기의 가독성을 우선한다.
- 기존 2.5D·Blender·v5b 규격은 레거시 비교 자료다. 새 PPU, 타일 크기,
  셀 크기와 동작별 프레임 수에 자동 승계하지 않는다.

## 일정 산정 가정

- 현재 프로젝트에는 이미 플레이 가능한 `RatHost2DPrototype` 씬,
  Floor·Wall·Water 2D Tilemap, 이동·충돌, 픽셀 카메라, Y축 정렬과
  Stage1~3의 숙주/내부 미니게임/변이 선택·복귀 핵심 루프가 있다.
  빠른 검증에서는 이 구조를 새로 만들지 않고 대표 아트만 교체한다.
- 사용자 계획의 기준 일정은 이 기존 기반을 재사용하는
  `빠른 검증 트랙`이다. `전담 제작 라인 1개`, 주 5작업일, 큰 병행
  작업 없이 순차 진행하는 경우를 기준으로 한다.
- 한 제작 라인은 `ChatGPT imagegen 후보 탐색 → 사람 선별 → 수작업
  도트 재제작·정리 → 승인된 Unity 반입 → Play·빌드 QA`를 포함한다.
- 아래 작업일은 달력일이 아니라 누적 작업일이다. 피드백 대기, 휴일,
  다른 기능 수정, 신규 도구 도입과 외부 의뢰 대기는 포함하지 않는다.
- 기간은 고정 납기나 보장이 아니다. 첫 플레이 가능한 아트 샘플을
  만든 뒤 방향·반복 타일·쥐 일관성의 실제 수정량으로 반드시 재산정한다.
- 금액은 산정하지 않는다. 인력 구성과 외주 조건이 확정되지 않았기
  때문이다.
- 최종 PPU, 내부 해상도, 타일·셀 크기, 보행 프레임 수, 조명 구현
  방식은 이 문서에서 확정하지 않는다. 비교 샘플과 사용자 수용 뒤
  별도 규격으로 승격한다.

| 조명·효과 | 하수도 명암, 수면·오염, 피해·면역 상승, 변이 조각·선택·통로 개방 피드백 | 배경보다 플레이 정보가 먼저 읽히고 환경 명암과 충돌하지 않는 효과 | 공통 팔레트·광원 방향, 위험·수집물 식별 규칙 |
| Unity 반입·QA | Sprite·Tile Import 후보, 타일맵·정렬·피벗 연결, 카메라 출력, UI 연결, Play·Windows 빌드 확인 | 타일 이음, 8방향 매핑, 피벗, 가림, 픽셀 떨림, 입력 가독성과 추적 기록 통과 | 각 자산 묶음 승인, Unity 수정 별도 승인, QA 시나리오 |

바이러스·백혈구·변이 조각은 1차 프로토타입 핵심 루프에 필요한 최소
내부 화면 자산이다. 빠른 검증 트랙 Q3에서 최소 방향·상태 스프라이트를
현재 피벗·충돌 구조에 맞추고, Q4에서 실제 전환·복귀 화면을 회귀한다.
여러 적·여러 내부 환경으로 확대하지 않는다.

## 선행 의존성과 병렬 가능 구간

### 반드시 먼저 또는 순차로 해야 하는 것

1. 목표 reference의 계승 요소와 금지 요소를 브리프로 고정한다.
2. 공통 격자·투시, 논리 픽셀 밀도, 팔레트·광원 방향, 피벗·정렬 후보를
   같은 시험 화면에서 비교한다.
3. 환경 기본 타일의 투시가 정해진 뒤 소품의 투시와 접지점을 맞춘다.
4. 쥐 외형·화면 점유율·피벗을 승인한 뒤 전체 8방향 보행을 확장한다.
5. 타일·캐릭터·소품이 한 화면에서 맞은 뒤 조명·효과의 강도를 조정한다.
6. 실제 자산 승인 뒤에만 Unity Import와 씬 연결을 별도 작업으로 한다.
7. Unity Play에서 통과한 뒤 Windows 빌드의 스케일·가독성을 확인한다.

### 규격 공유 뒤 병렬 가능한 것

- 환경 기본 타일 제작과 쥐 방향 일관성 시트 제작
- 환경 투시 승인 후 소품 세트와 최소 HUD 시각 정리
- 쥐 8방향 정지·보행 정리와 환경 장식 변형 제작
- 타일 이음 QA와 캐릭터 체형·피벗 QA
- Unity 반입 담당의 Import 프리셋 시험과 아트 담당의 남은 프레임 정리

UI는 월드 타일 제작과 병렬화할 수 있지만 기준 플레이 해상도와 정보
우선순위가 먼저 필요하다. 조명·효과는 환경과 쥐의 공통 명암이 보이기
전에는 최종화하지 않는다.

## 빠른 검증 트랙 — 사용자 계획 기준

현재 2D 씬·Tilemap·이동·충돌·카메라·정렬·Stage1~3 핵심 루프를
그대로 재사용한다. 새 시스템이나 전체 타일셋을 먼저 완성하지 않고,
대표 자산을 기존 씬에 넣어 실제 화면 방향부터 확인한다.

| 게이트 | 해당 구간 추가 작업량 | 누적 작업일 | 완료 정의 | 단축 근거 |
| --- | ---: | ---: | --- | --- |
| Q0 정적 후보 | 0.5~1일 | 0.5~1일 | 목표 목업을 기준으로 환경·쥐·최소 HUD의 정적 비교 후보를 확인함 | 승인된 목표 reference와 기존 화면 구도가 있어 새 브리프를 처음부터 만들지 않음 |
| Q1 기존 씬 재사용 첫 플레이 샘플 | 추가 1.5~3일 | 2~4일 | 대표 환경 타일, 소품 2~3종, 쥐 대표 3방향 정지·짧은 보행, 최소 HUD가 기존 씬에서 이동함 | Tilemap·이동·충돌·카메라·정렬·핵심 루프를 새로 구현하지 않음 |
| Q2 한 방 기본 정리 | 추가 3~4일 | 5~8일 | 한 하수도 방의 타일 이음, 대표 소품 정렬, 쥐 접지와 HUD 가독성을 기본 수준으로 정리함 | 기존 맵 배치·collider·sorting·HUD 연결부를 유지하고 아트 교체에 집중함 |
| Q3 쥐 8방향·핵심 효과 통합 | 추가 5~12일 | 10~20일 | 쥐 8방향 정지·보행, 면역·변이·통로 핵심 효과와 내부 바이러스·백혈구·변이 조각 최소 상태를 통합함 | 기존 입력·상태 전환·변이 로직에 스프라이트와 효과만 연결함 |
| Q4 반복 수정·빌드 회귀 안정화 | 추가 5~10일 | 15~30일 | 방향 전환, 타일 이음, 가림, 픽셀 떨림, UI·효과 가독성을 반복 수정하고 Play·요청된 Windows 빌드 회귀를 통과함 | 이미 검증된 Stage1~3 기능 기준을 재사용해 시각 회귀에 집중함 |

누적 하한과 상한은 각 행의 추가 작업량을 이전 행에 더해 계산한다.
예를 들어 Q2 `5~8일`에 Q3 추가 `5~12일`을 더하면 Q3
`10~20일`, 다시 Q4 추가 `5~10일`을 더하면 `15~30일`이다.

Q0의 정적 목업·비교 후보는 `반나절~1일`에 볼 수 있는 방향 확인
자료다. 반복 타일, 8방향 스프라이트, 애니메이션, 충돌·피벗 또는 최종
게임 에셋이 아니다.

## 신규 제작 전체/보수 상한 트랙

아래 `30~50일`은 현재 사용자 계획의 기본값이 아니다. 기존 씬을
활용하더라도 타일·UI·캐릭터·효과를 처음부터 높은 완성도로 넓게 만들고,
한 전담 라인이 순차 제작·수정·빌드 회귀까지 모두 수행하는 경우의
보수 상한이다.

| --- | ---: | ---: | ---: | --- |
| U0 규격·브리프 | 2~3일 | 2~3일 | 1주차 | 공통 격자·투시·픽셀·피벗 비교 규격과 전체 신규 제작 범위를 문서화함 |
| U1 1차 후보·기초 규격 | 추가 3~5일 | 5~8일 | 1~2주차 | imagegen 탐색 후보와 수작업 반복·피벗 시험을 비교함 |

U4는 U3 누적 `15~25일`에 추가 `5일`을 적용해 `20~30일`이다.
상·하한을 같은 규칙으로 더하므로 이전 표의 `추가 5~10일`과
`누적 20~30일` 사이 산술 불일치는 제거했다.

## 순차 일정과 2~3역할 병렬 일정

### 전담 1개 순차 라인 — 현재 기준

`Q0 0.5~1일 → Q1 2~4일 → Q2 5~8일 → Q3 10~20일 →
Q4 15~30일`

### 2역할 병렬 — 조건부 참고

`환경·소품·UI`와 `쥐·효과`를 나누고 Unity 통합은 공동 대응한다.

`Q0 0.5~1일 → Q1 1.5~3일 → Q2 4~6일 → Q3 8~15일 →
Q4 12~24일`

누적 증분은 `0.5~1`, `1~2`, `2.5~3`, `4~9`, `4~9일`이다.

### 3역할 병렬 — 조건부 참고

`환경·소품`, `쥐·효과`, `UI·Unity 반입·제작자 자체 점검`을 나눈다.

`Q0 0.5~1일 → Q1 1.5~2.5일 → Q2 3~5일 → Q3 7~13일 →
Q4 10~20일`

누적 증분은 `0.5~1`, `1~1.5`, `1.5~2.5`, `4~8`,
`3~7일`이다. 여기서 자체 점검은 제작 중 확인이며, 루프 게이트의 독립
`QA/검증 에이전트` 판정과 프로젝트 총괄 검토는 별도로 유지한다.

병렬안도 고정 납기가 아니다. 첫 2~4일 플레이 샘플에서 타일 수정률,
방향별 쥐 재작업률과 Unity 통합 대기시간을 측정해 다시 산정한다.

## 기간이 길어지는 조건

이전 `30~50일`이 길었던 이유는 현재 구현을 활용한 첫 화면 확인이
아니라 다음을 한 순차 일정에 모두 포함했기 때문이다.

- 바닥·벽·수로·모서리·장식 변형을 처음부터 폭넓게 신규 제작
- 자연형 쥐의 전체 8방향과 보행 프레임을 높은 일관성으로 수작업 정리
- 프로토타입 UI와 내부 바이러스 화면 자산까지 한 번에 교체
- 최종 PPU·타일·셀·프레임 후보를 여러 번 비교
- 피드백마다 팔레트·명암·가림·피벗을 되돌려 반복 수정
- Play와 Windows 빌드의 여러 해상도·스케일 회귀를 충분히 수행
- 한 담당 라인이 후보, 재제작, 반입, 수정 대응을 대부분 순차 수행

따라서 지금 첫 결과를 보는 계획에는 Q1 `2~4일`을 사용하고, 높은
완성도의 전체 신규 제작이 실제로 승인될 때만 U5 `30~50일` 상한을
사용한다.

## 첫 실제 아트 작업 권장 묶음

첫 후속 작업은 기존 씬을 재사용하는 `2~4일 한 방 플레이 샘플 묶음`을
권장한다.

1. 기존 Tilemap에 교체할 대표 하수도 환경 타일
2. 투시와 정렬을 확인할 대표 소품 2~3종
3. 자연형 쥐의 측면·앞쪽 쿼터·뒤쪽 쿼터 대표 방향 정지와 짧은 보행
   시험
4. 숙주 생명력·면역 경계도만 포함한 최소 HUD
5. 기존 씬에서 교체 전·후를 비교하는 정지 화면과 짧은 이동 캡처

이 묶음은 전체 8방향이나 최종 UI를 완성하는 작업이 아니라, 타일 투시,
쥐 체형·접지, 화면 픽셀 밀도와 정보 우선순위를 조기에 검증하는 샘플이다.

착수 전에는 다음을 별도로 승인받아야 한다.

- imagegen 후보를 만들 자산과 후보 수, 입력 reference, 저장 위치
- 후보 선별 뒤 수작업 재제작 범위
- 대표 방향 시험 통과 뒤 쥐 8방향 정지·보행 확장
- 실제 Sprite·Tile Import와 Unity 씬 적용
- 첫 Unity 샘플 뒤 갱신한 일정과 다음 제작 묶음

## 범위 밖

- 전체 캠페인과 전체 스테이지 아트
- 벌레부터 인간까지 전 숙주 캐릭터와 전이 체인
- 병원·연구소·백신·엔딩 콘텐츠
- 완성형 로그라이크 전체 아이템·적·방 세트
- 최종 UI 전체와 모든 해상도·플랫폼 대응
- 최종 PPU·타일·셀·프레임 규격의 즉시 확정

## 검증 방법

- 문서 단계: 자산 누락, 선행 의존성, 누적 일정 산술, 승인 경계,
  프로토타입 범위를 독립 QA한다.
- 후보 단계: 출처·프롬프트·선별 상태와 목업/최종 에셋 구분을 확인한다.
- 에셋 단계: 타일 반복, 방향·프레임 체형, 공통 피벗, 투명 영역,
  팔레트·광원 일관성을 확인한다.
- Unity 단계: 실제 이동에서 타일 이음, 가림·Y정렬, 픽셀 떨림,
  효과·HUD 가독성을 확인한다.
- 수용 단계: Unity Play와 요청된 Windows 빌드 캡처를 목표 목업과
  비교하되, 목업의 픽셀을 그대로 복제했는지가 아니라 게임 규격에서
  같은 분위기와 우선순위를 달성했는지 판단한다.
