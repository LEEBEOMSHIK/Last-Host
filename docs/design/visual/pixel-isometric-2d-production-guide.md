# 2D 아이소메트릭 도트 제작 가이드

## 목적과 현재 상태

`마지막 숙주 / The Last Host`의 현재 승인된 시각·공간 표현은 Unity 기반 `2D 아이소메트릭 도트`다. 환경은 반복 가능한 2D 타일과 스프라이트, 캐릭터와 효과는 방향·상태별 2D 스프라이트로 제작한다. 고정 쿼터뷰 화면에서 이동, 충돌, 가림과 앞뒤 순서를 2D 규칙으로 처리한다.

목표 화면은 `references/rat-host-2d-isometric-gameplay-mockup-v1.png`다. 이 이미지는 품질과 분위기 reference이며 실제 타일셋·애니메이션·충돌 데이터가 아니다.

기존 `pixel-lowpoly-3d-production-guide.md`는 2026-07-27 이전 하이브리드 2.5D 방향의 이력과 기존 구현을 해석할 때만 사용한다.

## 1. 화면과 공간

- 시점은 회전하지 않는 고정 아이소메트릭 또는 이에 가까운 쿼터뷰를 사용한다.
- 월드는 공통 격자를 따르는 바닥·벽·수로·배관 타일과 독립 소품 스프라이트로 구성한다.
- 걷기 가능 영역과 충돌은 화면 장식이 아니라 별도 2D 데이터로 관리한다.
- 캐릭터와 소품의 앞뒤는 발 접지점의 Y 좌표 또는 명시적 정렬 레이어를 기준으로 처리한다.
- 벽 뒤 가림, 아치 통과, 큰 소품 앞뒤 이동을 대표 장면에서 검증한다.

## 2. 픽셀 규격

- 기준 내부 해상도와 타일 크기, 캐릭터 셀 크기, PPU는 첫 2D 플레이어블 기술 샘플에서 비교한 뒤 확정한다.
- 하나의 화면에서 환경·캐릭터·효과가 같은 논리 픽셀 크기로 보이게 한다.
- Point 필터, 밉맵 비활성화, 무손실 또는 무압축을 기본 시험값으로 사용한다.
- 이동 중 서브픽셀 떨림과 비정수 확대 흐림을 피한다.
- HUD·텍스트는 월드 픽셀 출력과 분리해 선명하게 유지할 수 있다.

기존 v5b의 `128×128`, `PPU 64`, 32색 제한은 2.5D 프리렌더 쥐의 레거시 규격이다. 새 2D 자산에 자동 승계하지 않는다.

## 3. 환경 타일과 소품

- 바닥, 벽, 수로는 반복 연결이 가능한 타일 변형을 가진다.
- 타일 경계에서 명암, 오염, 물결, 벽돌 줄눈이 끊기지 않아야 한다.
- 배경 디테일은 이동 경로, 위험, 수집물, 상호작용 지점보다 먼저 읽히지 않게 한다.
- 목업의 조밀함은 `반복 가능한 모듈 + 선택된 장식 변형`으로 재구성한다.
- 조명과 그림자는 픽셀 아트에 구워 넣는 방식과 제한적인 Unity 2D 효과를 비교하되, 방향이 충돌하지 않게 한다.

## 4. 캐릭터 스프라이트

- 쥐는 자연스러운 등–목–머리 곡선, 접지된 발, 읽히는 귀·코·꼬리를 우선한다.
- 정지·보행을 포함한 모든 방향에서 체형, 무늬, 귀 크기, 꼬리 길이, 화면 점유율이 같아야 한다.
- 기본 검증 대상은 8방향이다. 제작량 절감을 위한 좌우 반전은 비대칭 무늬·조명·행동을 검토한 뒤 결정한다.
- 모든 프레임은 같은 캔버스, 발 접지 피벗, 방향 이름, 프레임 순서를 사용한다.
- 프레임 교체가 충돌체·상호작용 위치를 바꾸지 않게 논리 루트와 시각 자식을 분리한다.

## 5. ChatGPT 이미지 생성의 역할

OpenAI 내장 `imagegen`은 다음 용도로 우선 사용할 수 있다.

- 목표 화면과 분위기 목업
- 캐릭터 외형 콘셉트와 턴어라운드 초안
- 타일·소품·HUD의 스타일 탐색 후보
- 색상·명암·밀도 비교안

생성 결과는 곧바로 최종 타일이나 애니메이션 시트가 아니다. 방향별 AI 이미지를 개별 생성하면 체형과 투시가 흔들릴 수 있으므로, 공통 reference·프롬프트와 일관성 시트를 사용하고 사람이 재제작·보정한다. 프롬프트, 도구, 날짜, 입력 reference, 출력 경로, 선별 이유를 작업 패킷에 남긴다.

세부 절차는 `../../prototype/plans/rat-host-ai-assisted-art-workflow.md`, 담당 역할은 `.agents/chatgpt-image-art-agent.md`를 따른다.

## 6. 최소 기술 샘플

전체 콘텐츠 제작 전에 다음을 하나의 작은 하수도 방에서 검증한다.

1. 실제 반복 타일 바닥·벽·수로
2. 자연형 쥐의 정지·보행 방향 스프라이트
3. WASD 이동과 고정 카메라 추적
4. 벽·수로 충돌
5. 소품·벽 앞뒤 정렬과 가림
6. 실제 해상도의 최소 HUD
7. Unity Play와 Windows 빌드

## 7. 수용 기준

- [ ] 목업과 비슷한 자연형 캐릭터, 명암 깊이, 환경 밀도를 실제 게임 규격으로 재구성했는가?
- [ ] 타일이 반복되고 경계가 끊기지 않는가?
- [ ] 정지·보행·방향 전환에서 캐릭터 체형과 피벗이 안정적인가?
- [ ] 플레이어·위험·수집물·이동 경로가 배경보다 먼저 읽히는가?
- [ ] 이동 중 흐림, 픽셀 떨림, 정렬 팝이 없는가?
- [ ] 생성형 이미지의 출처와 선별 기록이 있으며 최종 에셋과 구분되는가?
- [ ] 실제 Unity Play 화면과 목표 Windows 빌드에서 확인했는가?

## 8. 변경 경계

- Unity 씬·코드·패키지·Import 변경은 별도 작업 패킷과 승인·검증을 거친다.
- 인간·병원·연구소·백신·엔딩 등 프로토타입 밖 콘텐츠를 시각 시안에 임의 추가하지 않는다.
- 기존 2.5D 구현과 산출물은 전환 작업이 검증될 때까지 삭제하지 않고 레거시로 보관한다.
