# 그래픽 방향 관리 기준

## 현재 확정 방향

2026-07-27 사용자 승인에 따라 `마지막 숙주 / The Last Host`의 신규 시각·공간 제작 기준은 `2D 아이소메트릭 도트`로 전환되었다.

- Unity 엔진과 PC 우선 목표를 유지한다.
- 환경은 반복 가능한 2D 아이소메트릭 타일과 소품 스프라이트로 제작한다.
- 쥐·바이러스·백혈구·효과는 방향·상태별 2D 스프라이트로 제작한다.
- 이동·충돌·가림·앞뒤 정렬·카메라는 고정 쿼터뷰의 2D 규칙으로 재구성한다.
- 쥐 숙주, 면역 경계도, 내부 미니게임, 변이 선택과 복귀의 핵심 루프는 유지한다.
- 기존 3D 환경, 저폴리 원본, Blender 8방향 프리렌더 파이프라인은 신규 제작 기본 경로에서 제외하되 이력과 기존 구현 해석을 위해 보관한다.

## 목표 화면 reference

기준 이미지는 `references/rat-host-2d-isometric-gameplay-mockup-v1.png`다.

이 목업에서 계승할 요소:

- 자연스럽고 읽기 쉬운 쥐 실루엣
- 조밀하지만 이동 경로와 캐릭터가 묻히지 않는 하수도 환경
- 고정 아이소메트릭 시점과 명확한 깊이 단계
- 제한된 색과 픽셀 군집으로 표현한 재질·명암
- 월드와 분리되어 읽히는 최소 HUD

자동 확정하지 않는 요소:

- 타일 크기·셀 해상도·PPU
- 목업 내부의 정확한 투시와 오브젝트 배치
- 쥐의 실제 방향 수와 동작별 프레임 수
- HUD 아이콘·배치·수치
- 조명 구현 방식

출처와 한계는 `references/README.md`를 따른다.

## 기본 바이러스 character reference

기본 바이러스 외형은 `references/bacteriophage-base-character-reference-v1.png`와 `characters/base-bacteriophage-character.md`를 따른다.

- 큰 정이십면체 캡시드가 전체 높이의 약 60~70%를 차지한다.
- 몸통은 2~3마디로 짧게 유지하고, 팔 2개·다리 2개·작은 파지 꼬리만 둔다.
- spike protein은 짧고 둥글게 표현하며 보라·분홍·흰색 제한 팔레트를 사용한다.
- 호기심 많고 용감하며 친근하고 영리한 독창적 게임 마스코트로 읽혀야 한다.
- 업그레이드는 기본 실루엣을 유지한 채 작은 방어구, 발광 코어, 결정 성장, 에너지 효과, 캡시드 장식, 진화한 spike 같은 제한적 추가요소를 사용할 수 있다.

reference의 3D voxel·재질·조명은 production 방식이 아니다. 실제 제작은 방향별 2D 아이소메트릭 도트 스프라이트로 재설계하며, 특정 회사·캐릭터 스타일 모사 문구를 승계하지 않는다. 이미지의 크기·행동·업그레이드 설명도 기획 규칙으로 자동 확정하지 않는다. 실제 턴어라운드·시트·애니메이션·Unity 적용은 별도 승인 대상이다. 기존 A/B/C 바이러스 후보는 `SUPERSEDED` 탐색 이력이다.

## 참고 게임

`Dave the Diver`와 `The Binding of Isaac`은 픽셀 밀도, 실루엣, 명도 깊이, 플레이 우선순위만 비교하는 참고다. 캐릭터, 적, 방, 아이템, UI, 고유 모티프와 화면 구성을 복제하지 않는다.

## 프로젝트 그래픽 원칙

1. **플레이 규격으로 재제작한다.** 목업·AI 후보를 잘라 쓰지 않고 반복 타일, 방향별 스프라이트, 피벗, 충돌과 정렬 데이터로 재구성한다.
2. **자연스러운 쥐를 유지한다.** 쥐의 등–목–머리 곡선과 발 접지, 귀·코·꼬리의 읽힘을 보존하되 작은 화면에서 과도한 털 노이즈는 줄인다.
3. **같은 픽셀 세계를 만든다.** 환경·캐릭터·효과의 논리 픽셀 크기, 외곽선, 명암 방향과 색 밀도가 서로 어울려야 한다.
4. **게임플레이가 먼저 읽힌다.** 플레이어·위험·수집물·상호작용·이동 경로가 장식보다 먼저 보여야 한다.
5. **방향과 프레임이 안정적이어야 한다.** 체형·무늬·피벗·화면 점유율이 정지·보행·방향 전환에서 흔들리지 않아야 한다.
6. **월드와 UI를 분리한다.** 월드는 도트 규격을 유지하고 HUD·텍스트는 필요한 경우 별도 선명 레이어로 표시한다.

## ChatGPT 이미지 연계

OpenAI 내장 `imagegen`은 외형 콘셉트, 목표 화면 목업, 타일·소품·HUD 탐색 후보 제작에 우선 사용할 수 있다. 담당은 `ChatGPT 이미지 아트 에이전트`다.

- 프로젝트 reference와 승인된 브리프를 입력으로 사용한다.
- 프롬프트, 생성 도구, 날짜, 입력 출처, 출력 경로, 후보 번호와 선별 결과를 기록한다.
- 결과는 사람 선별 전 후보이며 최종 타일·스프라이트 시트로 자동 승인하지 않는다.
- 방향·프레임별 결과의 체형, 투시, 팔레트와 피벗 일관성을 별도 QA한다.
- 실제 게임 에셋 제작과 Unity 적용은 각각 별도 작업·승인을 거친다.

세부 절차는 `../../prototype/plans/rat-host-ai-assisted-art-workflow.md`를 따른다.

## 픽셀아트 모션 코믹형 시네마틱

도입, 중요 숙주 전이, 세계 변화와 엔딩 같은 주요 서사 컷신은 제한 애니메이션 기반 `픽셀아트 모션 코믹형 시네마틱`을 기본 형식으로 사용한다.

- 게임과 같은 캐릭터 정체성, 제한 팔레트, 명암 방향과 논리 픽셀 크기를 유지한다.
- 배경·중경·전경·캐릭터·효과·마스크를 분리하고 카메라, 제한 패럴랙스와 핵심 포즈·표정 교체로 움직임을 만든다.
- 생성형 이미지 결과는 스토리보드·기준 원화·레이어 후보이며 최종 픽셀 레이어, 애니메이션 프레임이나 완성 컷신이 아니다.
- 자막과 UI 글자는 이미지에 굽지 않고 언어별 문자열과 폰트 fallback이 가능한 별도 레이어로 둔다.
- 실제 이미지·영상·애니매틱·오디오 제작과 Unity 재생 구현은 각각 별도 승인 대상이다.

상세 숏 설계, 레이어 명세, 비최종 애니매틱 계획, 역할 분리와 Unity 인계 기준은 `../narrative/pixel-art-motion-comic-cinematic-guide.md`를 따른다.

## 변경 관리

- 기준 해상도, 타일 크기, PPU, 방향·프레임 수, 팔레트의 공통 규격 승격은 기술 샘플과 사용자 수용을 거친다.
- 생성형 이미지와 시각 시험안은 `_workspace/active/<작업ID>/`에 입력 reference, 출력, 선별, 폐기 사유와 남은 위험을 기록한다.
- 기존 2.5D 자료는 삭제하지 않고 `pixel-lowpoly-3d-production-guide.md`와 완료 작업 기록에서 레거시로 추적한다.
