# 픽셀아트 모션 코믹형 시네마틱 가이드

## 1. 목적과 적용 상태

이 문서는 `마지막 숙주 / The Last Host`의 도입, 중요 숙주 전이, 세계 변화와 엔딩 같은 주요 서사 장면을 **픽셀아트 모션 코믹형 시네마틱**으로 설계하기 위한 공통 기준이다.

이 형식은 프로젝트의 기본 컷신 방향으로 승인되었다. 다만 이 문서가 승인하는 것은 **형식과 역할 인계 기준**뿐이다. 개별 장면의 제작, 생성형 이미지 사용, 애니매틱 파일 제작, 오디오 제작과 Unity 적용은 각각 별도 작업·승인을 거쳐야 한다. 현재 승인된 쥐 숙주 프로토타입 범위를 전체 캠페인으로 확대하지 않는다.

관련 상위 흐름은 [메인 시나리오·화면 흐름 초안](main-scenario-outline.md)을 따른다.

생성형 이미지 후보의 실제 에셋 가공·Unity Import가 포함된 장면은 [픽셀 시네마틱 제작·검증 재발 방지 플레이북](cinematic-production-failure-prevention-playbook.md)의 Gate 0~7과 상태 구분을 함께 따른다. 이 플레이북은 `loop-engineering-gates.md`를 대체하지 않는다.

## 2. 형식 정의

픽셀아트 모션 코믹형 시네마틱은 한 장의 정지 화면을 순서대로 넘기는 슬라이드쇼와 풀 프레임 애니메이션의 중간 형식이다.

- 2D 도트로 만든 배경·인물·전경·효과를 깊이별 레이어로 분리한다.
- 카메라 패닝·줌, 제한적인 패럴랙스, 마스크 전환과 화면 구도를 이용해 시선을 이동시킨다.
- 캐릭터는 핵심 포즈, 표정 교체, 2~4프레임 반복 같은 제한 애니메이션을 사용한다.
- 바이러스 이동 흔적, 물방울, 빛, 입자와 화면 진동 같은 짧은 효과로 사건의 속도와 감정을 보완한다.
- 대사·내레이션·효과음·음악 큐는 이미지에 굽지 않고 별도 데이터와 레이어로 관리한다.

목표는 적은 프레임으로도 장면의 원인과 결과, 바이러스의 이동, 먹이사슬과 숙주 전이를 명확히 전달하는 것이다. 풀 애니메이션처럼 모든 요소를 계속 움직이는 것은 기본 요구가 아니다.

## 3. 사용 우선순위

### 3.1 우선 적용 장면

- 게임 최초 도입과 주인공 바이러스의 첫 등장
- 먹이사슬을 이용한 중요한 숙주 전이
- 자연 생태계에서 인간 생활권으로 넘어가는 최초 장면
- 관계나 생존 방식이 크게 바뀌는 핵심 변이·선택의 결과
- 엔딩과 짧은 후일담

### 3.2 인게임 연출을 우선할 장면

- 일반 상호작용과 반복 전이
- 숙주 탐험에서 내부 바이러스 모드로 들어가는 짧은 전환
- 변이 카드 개방과 숙주 복귀
- 플레이어가 직접 움직이며 이해할 수 있는 사건

컷신은 플레이어 입력을 오래 빼앗지 않는다. 같은 정보를 실제 플레이로 전달할 수 있다면 인게임 연출을 우선한다.

## 4. 장면 설계 단위

각 시네마틱은 먼저 `시퀀스`, 그 안을 `숏`으로 나눈다. 숏마다 다음 항목을 고정한다.

| 항목 | 필수 내용 |
| --- | --- |
| 숏 ID | 시퀀스명과 순번. 예: `INTRO-S03` |
| 서사 목적 | 이 숏에서 새로 이해해야 할 사실 또는 감정 1개 |
| 시작·종료 상태 | 이전 게임 화면과 다음 게임 화면의 연결 상태 |
| 권장 길이 | 초 단위 예상값. 확정 타이밍은 애니매틱 검토 뒤 결정 |
| 화면 구도 | 주 피사체, 시선 방향, 안전 영역, 전경·배경 관계 |
| 레이어 | 배경·중경·전경·캐릭터·효과·마스크 목록과 깊이 |
| 움직임 | 카메라, 패럴랙스, 포즈·표정, 반복 프레임, 효과 큐 |
| 텍스트 | 대사·내레이션·자막 ID와 등장·퇴장 시점 |
| 오디오 | 음악, 환경음, 효과음의 임시 큐와 강조 지점 |
| 전환 | 페이드, 컷, 마스크, 매치 컷 등 다음 숏 연결 방식 |
| 접근성 | 건너뛰기, 점멸·흔들림 완화, 읽기 시간 요구 |

한 숏에는 핵심 정보 하나를 우선한다. 화면 요소를 늘려 먹이사슬·바이러스 이동·감정 표현을 동시에 설명하지 않는다.

## 5. 스토리보드와 비최종 애니매틱 계획

### 5.1 스토리보드

- 주요 시퀀스는 서로 다른 구도 후보 2~3개를 먼저 비교할 수 있다.
- 각 패널에는 숏 ID, 길이, 카메라 방향, 레이어 이동과 자막 위치를 적는다.
- 후보는 방향 검토용이며 사용자 선택과 후속 제작·QA 전에는 최종 화면이 아니다.

### 5.2 비최종 애니매틱 계획

애니매틱 계획은 다음을 검토하기 위한 **비최종 프리비즈 명세**다.

- 숏 순서와 대략적인 길이
- 카메라 패닝·줌과 전환 타이밍
- 자막의 표시 순서와 최소 읽기 시간
- 임시 음악·환경음·효과음 큐
- 이전 게임 상태에서 시네마틱으로 들어오고 다시 플레이로 복귀하는 시점

이 단계는 완성 영상이나 게임 에셋을 만들지 않는다. 실제 애니매틱 파일 제작이 필요하면 별도 승인 작업으로 분리한다.

## 6. 레이어 분해 명세

레이어 분해는 이미지를 실제로 생성하거나 잘라내는 작업이 아니라, 제작 담당자가 재현할 목록·깊이·마스크·움직임 지시를 작성하는 단계다.

기본 레이어 후보:

1. 원경 배경과 대기층
2. 주요 환경 배경
3. 중경 오브젝트와 숙주 실루엣
4. 주인공 바이러스 또는 주요 캐릭터
5. 전경 가림 오브젝트
6. 바이러스 이동 흔적, 물방울, 빛, 입자 등 효과
7. 장면 전환용 마스크
8. Unity에서 별도로 표시할 자막·UI 안전 영역

각 레이어에는 화면 크기, 투명 배경 여부, 앞뒤 순서, 기준 피벗, 이동 범위, 반복 가능 여부, 마스크 관계와 가장자리 여유를 명시한다. 패럴랙스는 깊이를 읽히게 하는 최소 범위로 사용하며 픽셀 떨림이나 서로 다른 논리 픽셀 크기를 만들지 않는다.

## 7. 픽셀·모션 연출 기준

- 게임플레이와 같은 캐릭터 정체성, 제한 팔레트, 명암 방향과 논리 픽셀 크기를 유지한다.
- 카메라 이동은 장면의 정보 순서를 유도해야 하며 단순 장식으로 흔들지 않는다.
- 확대·축소는 픽셀 파괴와 보간 흐림을 피할 수 있는 정수 배율 후보를 우선한다.
- 한 숏에서 주 움직임은 1~2개로 제한하고 나머지는 보조 반복으로 둔다.
- 먹이사슬은 숙주 간 원인 관계가 보이게 하고, 바이러스는 흔적·입자·매치 컷으로 이동 경로가 끊기지 않게 한다.
- 점멸과 화면 흔들림은 접근성 설정으로 완화하거나 끌 수 있어야 한다.
- 시네마틱용 구도 변화는 게임플레이 카메라 규칙을 바꾸는 승인이 아니다.

최종 픽셀 규격 적합성은 비주얼/테크아트 에이전트가 검토한다.

## 8. 자막·언어·오디오

- 글자는 생성 이미지와 배경 레이어에 굽지 않는다.
- 대사·내레이션은 언어별 문자열 ID로 관리하고 Unity의 다국어 폰트·fallback 체계를 사용한다.
- 한국어·영어를 포함한 각 언어에서 줄바꿈, 글자 폭, 최소 표시 시간과 화면 안전 영역을 다시 확인한다.
- 중요한 사건은 음성이나 색만으로 전달하지 않고 자막, 아이콘 또는 화면 행동을 함께 사용한다.
- 오디오는 제작 전 단계에서 `음악 시작/감쇠`, `환경음`, `효과음`, `무음 강조`의 큐만 지정할 수 있다.
- 실제 음원, 성우, 합성 음성과 믹싱은 별도 승인·제작 범위다.

## 9. 생성형 이미지와 최종 에셋 경계

ChatGPT 이미지 생성은 스토리보드 구도, 기준 원화, 배경·캐릭터·효과 레이어의 **후보**를 탐색하는 데 사용할 수 있다.

- 이미지 생성은 `ChatGPT 이미지 아트 에이전트`가 승인된 수량과 브리프 안에서 담당한다.
- 프롬프트, 생성 도구, 날짜, 입력 reference, 출력 경로와 후보 상태를 기록한다.
- 생성 결과는 최종 픽셀 레이어, 애니메이션 프레임, 완성 영상이나 Unity 에셋이 아니다.
- 사용자가 후보를 선택한 뒤에도 비주얼/테크아트의 픽셀 적합성 검토와 게임 규격 재제작이 필요하다.
- 생성 후보에서 읽을 수 없는 글자·로고·스타일 모사·범위 밖 콘텐츠가 나오면 폐기 또는 재작업 대상으로 표시한다.

## 10. Unity 인계 명세

시네마틱 연출 에이전트는 Unity를 수정하지 않고 다음 명세를 Unity 씬/통합 구현 에이전트에 넘긴다.

- 시퀀스와 숏 ID, 재생 순서, 예상 길이
- 각 숏의 레이어 목록, 깊이, 피벗, 마스크와 모션 지시
- 카메라 위치·이동·줌·전환의 의도와 시간표
- 캐릭터 포즈·표정·제한 프레임 교체 시점
- 자막 문자열 ID, 표시 구간, 언어별 안전 영역
- 음악·환경음·효과음 큐 ID와 타이밍
- 시작 전 게임 상태, 입력 잠금 범위, 건너뛰기 규칙과 종료 후 복귀 상태
- 점멸·흔들림 완화 조건과 저장·재시청 요구
- 누락 에셋, 임시 플레이스홀더와 별도 승인 필요 항목

Unity Timeline, 씬, 프리팹, 코드, Import 설정과 실제 재생 구현은 별도 승인 뒤 `Unity 씬/통합 구현 에이전트`가 담당한다.

## 11. 역할과 승인 경계

| 활동 | 단일 책임자 | 이 역할이 하지 않는 일 |
| --- | --- | --- |
| 숏·스토리보드·레이어·비최종 애니매틱 계획·Unity 인계 명세 | 픽셀아트 시네마틱 연출 에이전트 | 이미지 생성, 픽셀 최종 판정, Unity 구현, QA, 후보 선택·내부 승인 |
| 생성형 이미지 후보와 생성 기록 | ChatGPT 이미지 아트 에이전트 | 시네마틱 최종 설계·선택·Unity 반입 |
| 픽셀 규격·팔레트·프레임 일관성 최종 검토 | 비주얼/테크아트 에이전트 | 후보 생성·Unity 구현·사용자 선택 |
| 방향과 후보 선택 | 사용자 | 내부 검증 역할 대행 |
| Unity 재생 구현과 연결 | Unity 씬/통합 구현 에이전트 | 시나리오 방향 결정·최종 QA |
| 독립 정적·재생 검증 | QA/검증 에이전트 | production 파일 수정·내부 승인 |
| 범위·승인·역할 충돌 내부 판정 | 프로젝트 총괄 관리자 에이전트 | 사용자 최종 선택·Unity 구현·QA 실행 |

어느 한 역할도 위 권한을 흡수해 완성 컷신을 자동 승인할 수 없다.

## 12. 제작 흐름

아래 흐름에서 이미지 생성·가공·Unity Import로 넘어갈 때는 재발 방지 플레이북의 source visual checkpoint와 사용자 수용 경계를 먼저 통과한다.

1. 승인된 시나리오 구간과 전달 목적을 확인한다.
2. 시네마틱 연출 에이전트가 숏 목록과 스토리보드 후보 명세를 작성한다.
3. 사용자가 방향과 제작할 후보를 선택한다.
4. 별도 승인을 받은 경우 ChatGPT 이미지 아트 에이전트가 이미지 후보를 생성한다.
5. 시네마틱 연출 에이전트가 선택 결과를 레이어·타이밍·비최종 애니매틱 계획과 Unity 인계 명세로 정리한다.
6. 비주얼/테크아트 에이전트가 실제 제작 규격과 픽셀 일관성을 검토한다.
7. 별도 승인 뒤 제작 담당이 레이어·프레임·오디오를 만들고 Unity 씬/통합 구현 에이전트가 재생을 연결한다.
8. QA/검증 에이전트가 현재 후보를 독립 검증하고 프로젝트 총괄 관리자가 내부 승인 가능 여부를 판정한다.
9. 사용자가 실제 화면과 감각을 최종 수용한다.

- [ ] 숏별 시작·종료 상태와 플레이 복귀 지점이 있는가?

- [ ] 바이러스의 이동 경로와 숙주 간 원인 관계가 읽히는가?
