# 2D 아이소메트릭 도트 스타일 규칙

## 현재 기준

- Unity 기반 2D 아이소메트릭 도트 게임이다.
- 환경은 반복 가능한 타일과 소품 스프라이트, 캐릭터·효과는 방향·상태별 스프라이트로 제작한다.
- 목표 화면은 `docs/design/visual/references/rat-host-2d-isometric-gameplay-mockup-v1.png`다.
- 목업은 분위기·품질 reference이며 실제 타일셋·스프라이트 시트가 아니다.
- 기존 하이브리드 2.5D와 Blender 프리렌더는 레거시다.

## 타일과 공간

- 한 장면 안의 바닥·벽·수로·소품은 공통 격자와 아이소메트릭 투시를 따른다.
- 반복 타일의 명암·줄눈·오염·물결이 경계에서 끊기지 않아야 한다.
- 걷기 가능 영역, 충돌, 가림은 장식 이미지와 분리한다.
- 앞뒤 정렬은 발 접지점 Y 또는 명시적 Sorting Layer를 기준으로 한다.
- 벽 뒤 이동과 큰 소품 앞뒤 통과를 실제 플레이에서 검증한다.
- 가림·충돌 결함을 renderer/object disable, alpha 0, teleport·clamp, 입력 잠금, 가시 footprint보다 큰 invisible collider로 숨기지 않는다.
- QA는 플레이어 active/enabled/alpha·transform·입력 보존과 가시 footprint 대비 collision tolerance를 사용자 화면 oracle과 함께 확인한다.
- workaround는 사용자 명시 승인·임시 표시·제거 조건이 있을 때만 허용하며 완료가 아닌 `temporary` 또는 `blocked`로 남긴다. 실행 판정은 `docs/agents/loop-engineering-gates.md`를 따른다.

## 캐릭터

- 쥐는 자연스러운 실루엣과 지면 접지를 우선한다.
- 방향·프레임마다 몸통 길이, 귀·코·꼬리, 무늬와 화면 점유율이 같아야 한다.
- 같은 캔버스, 피벗, 방향 이름, 프레임 순서를 사용한다.
- 최종 셀 해상도·PPU·프레임 수는 2D 기술 샘플에서 확정한다.
- 기존 v5b `128×128`, `PPU 64`는 자동 승계하지 않는다.

## 픽셀 출력

- Point 필터와 밉맵 비활성화를 기본 시험값으로 사용한다.
- 환경·캐릭터·효과가 같은 논리 픽셀 크기로 보여야 한다.
- 이동 중 서브픽셀 떨림, 보간 흐림, 정렬 팝을 확인한다.
- 캐릭터·위험·수집물·이동 경로가 배경 장식보다 먼저 읽혀야 한다.
- HUD·텍스트는 필요하면 별도 선명 레이어로 표시한다.

## ChatGPT 이미지

- OpenAI 내장 `imagegen`을 우선한다.
- 프로젝트 reference, 프롬프트, 생성일, 입력 출처, 출력 파일과 선별 상태를 기록한다.
- 결과는 콘셉트·목업·탐색 후보이며 자동 최종 승인하지 않는다.
- 방향·프레임 일관성은 체형·투시·팔레트·광원·피벗을 함께 비교한다.
- 실제 타일·스프라이트는 반복·투명·피벗·애니메이션 규격으로 사람이 재제작·정리하고 QA한다.

## 프로토타입 기준

- 전체 전환 전에 작은 하수도 방, 실제 반복 타일, 자연형 쥐 정지·보행, 충돌, 정렬, 카메라, HUD를 하나의 기술 샘플로 검증한다.
- 최종 아트보다 조작감과 핵심 루프 검증을 우선하되, 목업과 플레이스홀더를 혼동하지 않는다.
- Unity Play와 Windows 빌드에서 가독성과 픽셀 안정성을 확인한다.
