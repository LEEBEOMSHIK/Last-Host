# Unity 구조 기준

## 전제

- 엔진은 Unity `6000.4.6f1`을 유지한다.
- PC 우선 프로토타입을 목표로 한다.
- 신규 비주얼·공간 제작 기본 방향은 목업을 목표 품질 reference로 삼는 2D 아이소메트릭/쿼터뷰 도트 방식이다.
- 환경은 Tilemap 또는 동등한 2D 레이어, 캐릭터와 효과는 방향별 2D 도트 스프라이트를 사용한다.
- 기존 3D 플레이어블 씬과 검증 자료는 레거시 회귀 기준으로 보존한다.
- 전체 전환 전에 별도 2D 플레이어블 기술 샘플을 구현·검증하고 사용자 플레이 승인을 받는다.
- 현재 URP 구성을 즉시 바꾸지 않는다. 2D Renderer, Pixel Perfect Camera 또는 추가 패키지가 필요하면 기술 샘플 계획에서 별도 승인 항목으로 올린다.

## 2D 기술 샘플 구조 기준

- 기준 화면 후보: `960x540`, 16:9. 최종 내부 해상도와 PPU는 실기 검증 후 확정한다.
- 카메라: 회전하지 않는 고정 직교 쿼터뷰와 플레이어 추적
- 공간: 반복 가능한 하수도 타일 또는 동등한 그리드 기반 2D 레이어
- 충돌: 2D Collider와 명시적 충돌 레이어
- 깊이: 발밑 기준 Y 정렬 또는 동등한 결정론적 Sorting Order 규칙
- 캐릭터: 같은 캔버스·피벗·화면 점유 크기를 유지하는 방향별 정지·보행 스프라이트
- 검증: 입력-화면 방향 정합, 카메라-쥐 중심 유지, 순간이동 없음, 벽·수로 충돌, 가림, 픽셀 흔들림과 HUD 가독성

## 시스템 경계

- `Core`: 게임 상태, 모드 전환, 공용 이벤트
- `Host`: 쥐 숙주 이동, 상호작용, 숙주 생명력
- `Immune`: 면역 경계도, 상승/감소 규칙
- `VirusMinigame`: 내부 바이러스 이동, 백혈구, 변이 조각
- `Mutations`: 변이 선택, 효과 적용
- `UI`: 게이지, 모드 표시, 변이 선택 화면

## 씬 후보

- `RatHostPrototype`: 현재 3D 플레이어블과 회귀 검증 기준
- `RatHost2DTechnicalSample`: 별도 승인 후 만들 2D 하수도 기술 샘플 후보
- `Bootstrap`: 필요성이 검증된 뒤 공용 초기화 후보
- `VirusMinigamePrototype`: 모드 분리 필요성이 검증된 뒤 내부 바이러스 미니게임 후보

초기에는 기존 3D 씬을 건드리지 않고 2D 기술 샘플 씬 하나로 검증한다. 샘플의 사용자 승인 전에는 전체 핵심 루프를 옮기거나 씬을 과하게 나누지 않는다.

## 승인 전 확인

- Unity 버전
- 현재 URP 유지 범위와 2D Renderer 필요 여부
- Input System 사용 여부
- 테스트 프레임워크 사용 범위
- 2D Tilemap/레이어, PPU, 타일 격자와 기준 화면
- 2D Collider, Sorting Layer/Y 정렬 규칙
- 기술 샘플용 플레이스홀더·ChatGPT 이미지 reference와 실제 게임 에셋의 경계
- 기존 3D 씬·프리팹·검증 자료의 보존 기간과 전환 시점
